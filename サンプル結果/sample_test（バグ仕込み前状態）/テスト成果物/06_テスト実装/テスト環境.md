## 起動のしかた

1. 配信が動いているかを確かめる: `curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/retirement_simulator.html` が `200` を返す。
2. 動いていなければ、PowerShell で `python -m http.server 8000 --bind 127.0.0.1 --directory D:\codes\sample_test` を起動する(止めるまで動き続ける)。
3. テスト実行の前に、テスト対象の SHA-256 が上の表と同じかを確かめる(`sha256sum "D:/codes/sample_test/retirement_simulator.html"`)。違ったら、テストマネージャーに報告する。

開くURL:

- http: `http://localhost:8000/retirement_simulator.html`
- file://: `file:///D:/codes/sample_test/retirement_simulator.html`

## 結果の欄の読み方

スモークテストで画面を開いて確かめた、結果の欄の書き方。

- 月の見出しの行: `-- <年齢>歳<月>月 --`(例: `-- 30歳1月 --`)。
- 月のかたまり: 月の見出しの行から、次の `-- ` か `== ` で始まる行の前まで。その中に、次の行が出る。
  - 収入の行(1行): `給与: ¥<額> (投資: ¥<額>)`(後ろに ` [年収: ¥<額>]` が付くことがある)、`退職後収入: ¥<額>`、`年金: ¥<額>` のどれか。収入の種類は行の先頭の語で、「給与の額」は `給与: ¥` の後の額。
  - 生活費の行: `生活費: ¥<額>`。
  - 突発的な支出の行(0行以上): `▶ <名前>: ¥<額>`。
  - 投資からの取り崩しの行(0行以上): `🔄 投資から補填: …`。取り崩しの額と税金は Q-010 の回答待ちなので、判定には使わない(取り崩した月は「投資が前の月より減った月」で見る)。
  - 残高の行: `現金: ¥<額> 投資: ¥<額> 総資産: ¥<額>`。
- 月のかたまりの外に、年の初めに `== <年齢>歳 1月: 投資利息 ==` の行と `投資: ¥<額> → ¥<額>` の行が出ることがある。月のかたまりには含めない(利回りのかけ方は Q-009 の回答待ちなので、判定には使わない)。
- 額は `¥` の後の数字。`,` を除いて数にする。`-` が付けば負の数。

## 手順を試したこと

PROC-001(LTC-092)を、手順のとおりに一度試した。テスト結果にはしていない。

- SHA-256 は `sha256sum` と `Get-FileHash` のどちらでも計算でき、テスト計画の値と比べられた。ファイルは 258 行で、Read で行番号つきで全行を読めた。
- 検索は、Claude の Grep(`-i`)と `grep -ni -e` でできた。最初に `grep -niF` を使ったところ、このPCの Git Bash では異常終了して何も出さず、0件と見分けがつかなかった。手順を `grep -ni -e` に直し、検索語を正規表現の書き方(`\.` `\(`)にした(テスト手順.md、ソースのチェックリスト.json)。
  - 注記: この書き方では4語が終了コード2で止まっていた。RB-003 で PROC-001 を grep -niE -e に直した。
- 手順に無い操作を足さずに、準備から事後条件の確かめまで進められた。

## 探索的テストの環境

- 道具: Claude の内蔵ブラウザで `http://localhost:8000/retirement_simulator.html` を開く(file:// は操作できないので使わない)。
- 入力: 欄を ref(read_page か find で得る)でトリプルクリックして値を選び、キーを打つ。空欄にするときは選んで Delete。
- 注意(スモークテストでわかったこと):
  - 内蔵ブラウザの画面が隠れているときも操作はできるが、read_page と find は、非表示の給与変更設定の欄の中のもの(見出し・追加ボタン)も出す。見えているかどうかは、スクリーンショットか、`#salaryChanges` の表示の状態で確かめる。
  - 空の給与変更の欄は、read_page で placeholder(`35`、`4000000`)が名前として出る。値が入っているように見えるので取り違えない。
  - 乱数は差し替えない(実行のたびに結果が変わるのは、そのまま観察の対象。CH-012)。
- ネットワーク要求とコンソール: read_network_requests と read_console_messages で見る(どのセッションでも外部への要求が無いかを確かめる)。コンソールには、画面を開くたびに上のエラーが2つ出る。
- 時間を計る(CH-009): JavaScript で `const t0 = performance.now(); document.getElementById('runBtn').click(); performance.now() - t0` を実行する。
- テストデータ: `テストデータ/探索的テスト.json`(TD-014)と、テストスイートの探索的テストの表に書いたファイル。
