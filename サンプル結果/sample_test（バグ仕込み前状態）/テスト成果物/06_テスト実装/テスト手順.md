# テスト手順

手動テストのローレベルテストケースの手順。実施方法がE2E自動テストのものは、`create-e2e-scripts` でスクリプトにするので、ここには書かない。

| ID | ローレベルテストケースID | 概要 | 依存 |
|---|---|---|---|
| PROC-001 | LTC-092 | テスト対象のソースを全行読み、外部へ送る書き方と外部のものを読み込む書き方が無いかをチェックリストで確かめる | なし(テストスイートの最初に行う。E2E自動テストと同時に行ってよい) |

## PROC-001

道具: ファイルを行番号つきで読む道具と、文字列で検索する道具(Claude の Read と Grep、または `cat -n` と `grep -niE -e`)。テスト対象のファイルは読むだけで、変えない。

- 検索語は拡張正規表現(ERE)として扱う。`.` と `(` は `\.` `\(` のように前に `\` を付ける(例: `\.submit\(`、`window\.open`、`url\(`)。Claude の Grep では `-i` を付ける。
- grep では必ず `-E` を付ける(例: `grep -niE -e '\.submit\(' "D:/codes/sample_test/retirement_simulator.html"`)。`-E` の無い `grep -ni -e` は基本正規表現(BRE)になり、`\(` を含む検索語(`\.submit\(` `url\(` `append\(` `require\(`)で `Unmatched ( or \(` を出して止まる。
- grep の終了コードを検索語ごとに確かめる。0 は当たりあり、1 は当たりなし(0件)、**2 はエラー**。2 のときは0件とみなさず、そこで止めて、検索語の書き方を直してから検索し直す。
- このPCの Git Bash では `grep -iF`(固定文字列の指定)が異常終了して何も出さない(手順を試したときに確かめた)。何も当たらなかったのか、異常終了したのかを取り違えないよう、`-F` は使わない。

### 準備

1. テストデータ `テストデータ/ソースのチェックリスト.json`(TD-013)を開き、チェックリストの4項目と検索語、SHA-256 を手元に置く。
2. テスト対象 `D:\codes\sample_test\retirement_simulator.html` の SHA-256 を計算する(Bash: `sha256sum "D:/codes/sample_test/retirement_simulator.html"`、PowerShell: `Get-FileHash -Algorithm SHA256 "D:\codes\sample_test\retirement_simulator.html"`)。
3. 2 の値が TD-013 の `SHA-256` と同じかを比べる。違ったら、ここで止めてテストマネージャーに報告する(テストアイテムが変わったため。テスト計画のとおり)。
4. 記録用に、次の表を用意する: `| 項目 | 行 | 書かれていること | 外部へ送る・外部を読み込むか | 判断の理由 |`

### 操作と確認

1. ファイルの全行を、行番号つきで最初から最後まで読む。最後の行の番号を記録する(読み落としが無いことの目安)。
2. チェックリストの項目 1(外部へ送る呼び出し)の検索語を1つずつ、大文字小文字を区別せずに検索する。どの検索語でも、当たった行が0件だったとき(grep なら終了コードが 1 のとき)は「0件」と記録する。終了コードが 2 のときは、上の決まりのとおり止めて検索し直す。当たった行はすべて、前後の行と合わせて読み、外部へ送る呼び出しかどうかを判断して、記録の表に書く(例: 文章の中の「ネットワーク通信」という語は呼び出しではない)。
3. 項目 2(外部のURLを指す src・href・action、CSS の url() と @import)の検索語で、2 と同じことをする。`//` は、コメントの `//` と URL の `//` を読み分ける。
4. 項目 3(外部のURLを持つ要素を後から作る処理)の検索語で、2 と同じことをする。要素を作る処理が当たったら、作る要素に src・href・action などで外部のURLが入るかを、作る処理の中身(文字列やテンプレート)を読んで判断する。
5. 項目 4(外部のライブラリを読み込む書き方)の検索語で、2 と同じことをする。`<script` が当たったら、src 属性があるかを見る。
6. 1 で読んだ全行のうち、2〜5 の検索語に当たらなかった行にも、外部へ送る・外部を読み込む書き方が無かったかを振り返り、あれば記録の表に書く(検索語は手がかりで、検索に当たらない書き方もありうるため)。
7. 期待値と比べる: 記録の表で「外部へ送る・外部を読み込む」と判断した行が0件なら期待値を満たす。1件以上あれば満たさない(その行番号と書かれていることを、テスト結果と欠陥レポートに書く)。
8. 事後条件を確かめる: 準備の 2 と同じ方法で SHA-256 をもう一度計算し、準備の 2 の値と同じであることを確かめる。

### 後片付け

- テスト対象のファイルは読むだけなので、元に戻すものは無い。記録の表は、テスト実行の証跡としてテストランのフォルダに置く。
