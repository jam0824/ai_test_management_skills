## テストメモ

詳しい値は証跡 SES-021_01。

1. 10:47 周1 給与変更 40.5歳 600万(欄は stepMismatch)→ 41歳1月から 600万。期間の戻り0、つじつまの合わない月0(781か月)。注意なし → 開始年齢も整数でなくして、給与変更の年齢とそろうかを見る
2. 10:47 周2 開始30.5 → 40.5歳1月から 600万(年齢の並びが 30.5, 31.5, … になり、給与変更の年齢とちょうどそろう)。最後は 99.5歳12月(BUG-005 に既出)→ 給与変更の年齢の欄の上限(max="100")を超える 100.5 を見る
3. 10:47 周3 退職101、給与変更 100.5歳 → 欄は「値は 100 以下にする必要があります。」で不正、給与変更は使われない(計算の最後より後なので。SES-006 の 101歳の年金開始年齢と同じ形)→ **給与変更の年齢が退職年齢より前なのに使われない**組を探す
4. 10:47 周4 退職40.8、給与変更 40.2歳 → 30〜40歳は基本年収のまま、41歳から退職後。**退職年齢(40.8)より前の年齢(40.2)の給与変更が一度も使われない**([年収] の行0件)。年齢は1年ごとの整数で比べるので、40歳では 40.2 に届かず、41歳ではもう退職している。注意なし → 指数表記の年齢と、円未満の年収を見る
5. 10:48 周5 給与変更の年齢「4e1」・年収 6000000.567 → 40歳から使われ、「[年収: ¥6,000,000.567]」と**年収の円未満がそのまま表示される**(BUG-009 は取り崩しと利息の行。[年収] の行は新しい場所)。つじつまは合う(781か月)→ 0歳の給与変更が使われない(BUG-015)のに対して、0 に近い年齢ならどうかを見る
6. 10:48 周6〜周8 0.5歳 900万を足し開始0 → 0歳は基本年収、1歳から 900万。開始0.5 なら 0.5歳1月から 900万。0.0001歳でも 1歳から。期間の戻り0、つじつまの合わない月0(1,111か月)。0歳の給与変更が使われないのは `0` ちょうどだけで、0 より大きい年齢は次の整数の年齢から使われる → 周4 の「使われない給与変更」が退職年齢を変えるとどうなるかを見る
7. 10:48 周9〜周12 給与変更 40歳・40.2歳、退職 40.8 / 42 / 41、年金 40.5 → 退職42 なら 40.2歳の設定は41歳から使われる。退職41・40.8 では使われない。年金開始年齢 40.5 は41歳から年金(退職後の期間なし)。どの周も期間の戻りは0、つじつまの合わない月も0。100歳12月の現金と投資の和と総資産が1円違う(BUG-010 と同じ)→ 時間枠に届いたので、ネットワーク要求とコンソールを確かめて終えた

思いついたリスク・アイデア:
- 年齢は整数の歳ごとに比べるので、整数でない年齢の給与変更・退職・年金開始は「次の整数の歳」に切り上がる。給与変更の年齢と退職年齢が同じ整数の歳の中にあると、給与変更は退職年齢より前でも使われない

## 課題

- 整数でない年齢を「次の整数の歳」として扱うことの是非は、Q-016(小数の年齢)の回答待ち。給与変更の年齢の欄は max="100" だが step の指定が無く、ブラウザは小数を不正(stepMismatch)と判定している
- ネットワーク要求: このセッションの間の記録は1件増えた(画面を開き直した1回、`GET http://localhost:8000/retirement_simulator.html → 200 OK`)。外部への要求は無かった。給与変更の追加でも要求は無い。コンソールは既知の「gap income line」「gap expense line」だけ(証跡 SES-021_01)
