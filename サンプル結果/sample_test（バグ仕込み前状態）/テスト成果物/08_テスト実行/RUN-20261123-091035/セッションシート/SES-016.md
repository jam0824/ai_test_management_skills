## テストチャーター

CH-007: 給与変更の年齢・年収を、負の値・整数でない年齢・数字でない文字で探索し、利用者に知らされるか、設定が黙って使われなくなるかを見つける。対象の領域は給与変更設定と「開始」、結果の表示。時間枠15分。リスク: 入れた設定が使われなかったことに利用者が気づける手がかりが何も無いまま、結果を出す。合否の基準は Q-016 の回答待ち。

このセッションは、SES-004(4分)で時間枠に届かなかった分を埋める続きのセッション(少なくとも11分)。

前のセッションでわかっていること(SES-004、欠陥レポート): 給与変更は、年齢・年収のどちらかが 0・負・空・数として読めない値のとき、その1件が黙って捨てられ、ほかの給与変更は使われる(BUG-002、BUG-014、BUG-015)。整数でない年齢は、その値以上になる最初の年齢から使われる。年収 0.5 は「[年収: ¥0.5]」と出て使われる。「400万」は400円になる(BUG-017)。

SES-004 で試していないことを中心にした: 誤りを順に直していく流れ、直した後の結果、0 の近くの値(-0、1e-7、0.0001)、2行以上の組み合わせ(同じ年齢、減額のつもりの負の値)、退職年齢・開始年齢との組み合わせ、矢印キー・マウスホイールでの直し方、マイナスに似た記号。

## テストメモ

1. 給与変更を1つ追加し、年齢「-5」・年収 5000000 で「開始」→ 捨てられる(SES-004 のとおり)。年齢を 40 に直して「開始」→ 40歳1月から「給与: ¥298,458 [年収: ¥5,000,000]」300か月。続けて年収を -1 にすると捨てられ、6000000 に直すと 40歳1月から「[年収: ¥6,000,000]」300か月(証跡 SES-016_02 の1) → 直した後は、前の誤りの影響を残さずに使われる。直す流れそのものに問題は無い。次は、直したつもりで 0 の近くの値になる形を見る
2. 0 の近く: 年齢「-0」は欄が正しい値の状態なのに捨てられる(0 と同じ)。「-0.5」は捨てられる。「4e1」は欄に「4e1」と見えたまま 40 として使われる。「39.999」は40歳から → 「-0」は欄の見た目にマイナスがあるのに不正にならず、捨てられる。年収でも 0 の近くを見る
3. 年収「1e-7」「0.0001」→ 40歳1月から「給与: ¥0 (投資: ¥0) **[年収: ¥0]**」と使われる。「1e-400」(値は0に丸まる)と「-0」は捨てられる。(40, 0.0001) と (50, 0) の2行では、40歳から100歳まで「[年収: ¥0]」が続き、50歳の 0 の行は捨てられている。0.0004 は「¥0」、0.0005 は「¥0.001」と出る(年収の表示は小数3桁で丸める) → **結果には「[年収: ¥0]」と出て効いているように見えるのに、年収に 0 と入れた設定は使われない**。結果の表示から見ると、0円の給与変更が使えるかのように読める(BUG-002 の新しい再現条件。候補-SES-016-1)
4. 2行の組み合わせ: (40, -1) と (40, 5000000) → 5000000 が使われる。(40, 8000000) と (40, -5000000) → 8000000 → 同じ年齢でも、捨てられるのは不正な1件だけ。次は、減額のつもりで負の年収を入れる使い方を見る
5. (40, 8000000) と (50, -1000000)(50歳で100万円下がるつもり)→ 50歳の行は捨てられ、40歳から64歳まで「[年収: ¥8,000,000]」が続く。100歳12月の総資産 ¥269,065,000。(50, 7000000) と正しく入れると ¥251,947,076 → **減額のつもりの負の値は捨てられ、前の年収がそのまま続く**。50歳1月の行も「[年収: ¥8,000,000]」と出るので、捨てられたことに気づく手がかりは無く、約1,700万円楽観的な結果になる(BUG-015 の新しい再現条件。候補-SES-016-2)
6. 退職年齢 101 にして、(100, 7000000) → 100歳1月から12か月使われる。(99.5, 7000000) も同じ → 年齢の上限 100 の境目は、そのとおりに使われる
7. 矢印キーで直す流れ: 年収「-1」の欄で上矢印 → 0(欄は正しい値になる)。年齢「-5」で上矢印 → 0、もう一度 → 1。50.5 で下矢印 → 50、40.5 で上矢印 → 41 → 負の値を矢印キーで直すと、まず 0 になる。(40, 8000000) と (50, 0) で「開始」すると 50歳の行は捨てられる → **欄が正しい値の状態になったのに捨てられる**(候補-SES-016-2)
8. 年収「500万」→ 500円(BUG-017 に給与変更の欄の例がすでにある)。年収「ー300000」(長音記号)→ 欄は -300000 になり、捨てられる。年齢「５５」(全角)→ 55 → 打ち間違いの記号でも負の値になって捨てられる。マイナスに似た記号をもっと見る(15)
9. 行の削除: (40, 500) と (55, -300000) の1行目を削除 → 残るのは (55, -300000)、捨てられて基本の年収 → 削除は正しい行を消す。次は、ほかの欄との組み合わせ
10. 開始年齢 30.5 と (40, 5000000) → 「30.5歳1月」から120か月は基本の年収、「40.5歳1月」から年収500万円。(0.5, 5000000) → 開始から使われる。開始年齢 0 と (0.5, 5000000) → 0歳の12か月は基本、1歳1月から → 整数でない開始年齢と組み合わせても、「その値以上になる最初の年齢」の決まりのとおり
11. 4行: (50, -1)、(40, 6000000)、(45, 空。灰色の「4000000」が見える)、(55, 4000000) → 40歳から600万円180か月、55歳から400万円120か月。-1 の行と空の行は捨てられる。画面には「4000000」が2つ見えて、使われるのは1つだけ(証跡 SES-016_01) → 捨てられた行が何行あっても、画面にも結果にも数は出ない。欄の見た目(枠の色)は、正しい値の欄と不正の欄で同じ(rgb(118,118,118))。ブラウザは「値は 0 以上にする必要があります。」と判定しているが、画面には出ない
12. 開始年齢 100・退職年齢 101 で同じ4行 → 100歳1月から、100以下で最後の (55, 4000000) が使われる。開始年齢を超える年齢の行も、開始前の行として使われる
13. 退職年齢との境目: (64.5, 4000000)(退職65)→ **一度も使われない**(65歳からとして扱われ、65歳からは給与が無い)。(64, 4000000) なら64歳1月から12か月 → 整数でない年齢を切り上げた結果が退職年齢に重なると、その給与変更は丸ごと消える(BUG-005 の新しい再現条件。候補-SES-016-3)
14. (40.5, 5000000) と (41, 7000000) → 30〜40歳の132か月は基本、41歳1月から700万円。**40.5 の行の年収は一度も出ない** → 整数でない年齢を入れると、別の行と同じ年齢に重なって消える(候補-SES-016-3)
15. マイナスに似た記号: 年齢「−5」(数学のマイナス U+2212)→ 欄の値は 5(正しい値)で、**30歳1月から「[年収: ¥4,000,000]」と開始から使われる**。「－5」(全角のマイナス)→ -5 になり捨てられる。年収「−1000000」→ 1000000 になり、50歳1月から「給与: ¥66,917 [年収: ¥1,000,000]」。「−0」→ 0 で捨てられる → 同じ「マイナス」のつもりでも、記号によって「捨てられる」と「正の値として使われる」に分かれる。減額のつもりの「−100万」は、年収100万円として使われる(候補-SES-016-4)
16. マウスホイール: 年齢 40 の欄にフォーカスがあり、ポインタがその欄の上にある状態でホイールを1目盛り下へ → 39、さらに1目盛り → 38。上へ → 39。ページはスクロールしない(scrollY が変わらない)。ポインタが欄の外にあるときは、ページがスクロールし、値は変わらない → 年齢 1 でホイール下 → 0、「開始」すると捨てられる。年収 1 → 0 も同じで捨てられる。年齢 0.5 → 0。(チャーター外)退職年齢の欄でも 65 → 64 → 65 → **ページをスクロールしたつもりで、フォーカスのある欄の値が黙って変わる**。給与変更では、1 → 0 で設定が丸ごと捨てられる(候補-SES-016-5)。空の欄でホイール上・上矢印 → 1(灰色の「35」「4000000」から始まるのではない)。(1, 1) で「開始」すると、30歳1月から「給与: ¥0 [年収: ¥1]」420か月
17. (チャーター外)給与変更の年収の欄で Enter → 実行されない(BUG-026 の新しい再現条件)。行を追加しても、表示/非表示を切り替えても、ほかの行の値は残る。空の行を6つ足して「開始」しても NaN などは出ない。開き直すと行は0件・非表示に戻り、localStorage・sessionStorage は空
18. ネットワーク要求の記録(tab-7、セッションを通して)→ `GET http://localhost:8000/retirement_simulator.html → 200` の2件(画面を開いた2回)だけ。**外部への要求は0件**。コンソールのエラーは、画面を開くたびに出る既知の `gap income line` `gap expense line` の2つ×2回だけ
- 思いついたアイデア・リスク:
  - 捨てられ方の決まり(推測): 年齢・年収のどちらかが、数にして 0 以下か空なら捨てる。0 より大きければ、欄が不正(stepMismatch など)でも使う。だから「1e-7」「0.0001」は使われ、「-0」「1e-400」は捨てられる
  - 結果の「[年収: ¥0]」は、0円の給与変更が使えるかのように見せる。利用者が 0.0001 で効いたのを見て、0 でも効くと考えると、BUG-002 に気づきにくい
  - 矢印キー・ホイールで値を減らしていくと、最後は 0 になって捨てられる。欄は正しい値の状態のまま

## 課題
