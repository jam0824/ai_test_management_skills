# テスト計画

入力: `01_要求仕様/要求.md`(REQ-001〜REQ-013)、`01_要求仕様/仕様.md`(SPEC-001〜SPEC-064)、`02_リスク分析/リスク分析.md`(RISK-001〜RISK-045)、`質問表.md`(Q-001〜Q-018 は未回答)。テストのレベルはシステムテスト。

## テスト目的

老後資金シミュレーターが、README に書かれた機能と約束(要求 REQ-001〜REQ-013)のとおりに動くかを、システムテストで確かめる。特に次のことを確かめ、テストレポートで利用者の立場から「この結果を信じて資金計画に使えるか」を判断する材料として、依頼した人(テストマネージャーと、その先の判断者)に示す。

- 期間ごとの収入・生活費、手取り、投資、取り崩しの計算が、仕様のとおりに資産の推移へ反映されること(REQ-002〜REQ-007)。リスク分析で区分が高のリスクの多くがここにある
- 結果から、資金が尽きるかどうか・いつ尽きるかを利用者が読み取れること(REQ-008)
- README が最も強く約束している「入力した財務情報を外部に送らない」「ネットワークが無くても動く」が守られていること(REQ-009、REQ-010)
- ありえない値を入れたときにどう振る舞うか(REQ-013)。仕様が無いので、振る舞いを明らかにして判断者に渡す

## 対象外/制約

### 対象外

| 対象外にするもの | 理由 | 残るリスク |
|---|---|---|
| Safari での動作(SPEC-061) | テスト環境が Windows だけで、Safari を動かせない。Windows で動く Safari は無い | Safari 固有の入力欄・数値表示の違い(RISK-041 のうち Safari の分)は確かめられない。RISK-041 は区分が低(リスクレベル6)で、標準の機能だけで作られているため、対象外にする。参考として Playwright の WebKit でE2E自動テストを流す(TA-018 の備考)が、WebKit は Safari そのものではないので、SPEC-061 を確かめたことにはしない。テストレポートでは、SPEC-061 を「対象外のため未確認」と書く |
| 付属のテストファイル `test_retirement_simulator.html` | 受け取ったフォルダに無い(Q-018 で確認中) | 付属のテストで確かめているはずの内容(手取り計算テストなど)は、資料としても使えない。テスト対象の動きは、このテストで確かめる |
| ユニットテストなど、E2E自動テスト以外の自動テスト | このテストはシステムテストのレベルで行う | 計算の関数単位の誤りは、画面の結果を通してしか見つけられない |
| 税制・年金制度が実際の制度として正しいか | README の注意事項で「目安」とされ、制度の変更は考慮しないとある(SPEC-034)。確かめるのは仕様どおりに計算しているかまで | 実際の税額と違っても、仕様どおりなら不具合にしない |
| 実際にネットワークを切った状態(OSのネットワーク設定を変える) | このPCのシステム設定は変えない | オフラインは Playwright のオフラインの設定で再現する(TA-017)。OSの設定で切ったときとの違いは確かめない |

### 制約

- テスト環境は、このPCのローカル環境(127.0.0.1:8000 と `file://`)だけ。外部のサービスやほかの環境には触らない。
- 使えるもの: Windows 11、Python 3.11、Node.js v22.19.0、Chrome と Edge(インストール済み)、手動テスト・探索的テスト用のブラウザ操作ツール(Claude の内蔵ブラウザ。Chromium系)。
- Playwright は未インストールで、E2E自動テストスクリプト作成の工程で入れる。Firefox はこのPCに入っていないので、Firefox の確認(SPEC-060)は Playwright の Firefox で行う。Playwright の Firefox は一般に配られている Firefox と同じものではないため、テストレポートではその旨を書く。
- 質問表の Q-001〜Q-018 は未回答。計算の期待値の多く(期間の境目、手取り、利回り、取り崩し、資金が尽きたとき、イベントの金額など)は回答待ちで、回答が来るまで、その部分のテストケースは実装も実行もされない。各テストアプローチの備考に、待っている質問のIDを書いた。
- 計算の期待値は、テスト対象の画面の実装から写さず、仕様(と質問の回答)からテストの側で計算する。画面の実装から写すと、実装の誤りをそのまま正解にしてしまうため。
- ランダムイベントは乱数で起きるので、E2E自動テストでは、テストの側で乱数(Math.random)を決まった値に差し替えて、結果が毎回同じになるようにする。差し替えはテストの中だけで行い、テスト対象のファイルは変えない。
- テストにかけられる時間の指定は受けていない。
