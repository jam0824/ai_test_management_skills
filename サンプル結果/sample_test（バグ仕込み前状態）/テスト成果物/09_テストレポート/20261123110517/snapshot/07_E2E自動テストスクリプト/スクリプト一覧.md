# E2E自動テストスクリプト

入力: `06_テスト実装/ローレベルテストケース.md`(実施方法がE2E自動テストの97件: LTC-001〜LTC-091、LTC-093〜LTC-098)、`06_テスト実装/テストデータ/`(TD-001〜TD-015)、`06_テスト実装/テスト環境.md`。テスト対象 `D:\codes\sample_test\retirement_simulator.html`(SHA-256 `87eaeced…22741`)。

- スクリプト本体は `D:\codes\sample_test\e2e\`(Playwright 1.65.1、JavaScript)。テストケースの中身は `e2e/tests/cases/*.js`、テストの登録は `e2e/tests/*.spec.js`、共通の部品は `e2e/tests/lib/`。
- ローレベルテストケース1件をテスト1件にし、テスト名の先頭にローレベルテストケースのidを付けた。テスト名の残りは、テストデータの「テストケース」と同じ。
- 条件・給与変更・乱数・比較用の実行・判定に使う値は、実行のたびに `テスト成果物/06_テスト実装/テストデータ/` の JSON から読む。テストデータに値として無いもの(LTC-004 の最初の開始年齢 40歳、LTC-090・LTC-091 の 35歳、LTC-005・LTC-006 のクリックの回数、期待値の年齢の範囲など)は、ローレベルテストケースの事前条件・操作・期待値から取り、スクリプトのコメントにそう書いた。
- 乱数は TD-002 のとおり、ページを読み込む前に `addInitScript` で Math.random を差し替える。「1か月だけ」「両端」は「開始」のクリックの直前に数を0に戻す。差し替えが効いていないとき(支出なしで `▶` が出た、など)は判定しない。
- 期待値は、ローレベルテストケースの期待値をアサーションにした。テスト対象と同じ計算をして期待値を作っていない。LTC-080〜LTC-084 の二項分布の範囲だけは、ローレベルテストケースの備考のとおり、数えた月の数 N からテストの側で計算する(N = 50,000 などのときの値が、ローレベルテストケースに書かれた範囲と同じになることを確かめた)。

## 実行のしかた

前提: `http://localhost:8000/retirement_simulator.html` が配信されていて(`curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/retirement_simulator.html` が 200)、テスト対象の SHA-256 がテスト環境.md と同じ。配信はスクリプトの側では立てない。

```powershell
cd D:\codes\sample_test\e2e
npx playwright test
```

- `--reporter` は付けない(付けると、設定ファイルの JSON レポートが出なくなる)。
- 流れるもの: プロジェクト `chrome`(インストール済みの Chrome。LTC-001〜LTC-091、LTC-093〜LTC-095 を1件ずつ)と、プロジェクト `browser-compat`(LTC-096 Chrome → LTC-097 Edge → LTC-098 Playwright の Firefox を、この順に1つの worker で流す)。worker は4つ(配信の http.server が、同時に多く接続すると断るため)。
- かかる時間: 試しに流したとき、全体で約8分30秒(`chrome` は約50秒。`browser-compat` は LTC-096 約2分40秒、LTC-097 約2分10秒、LTC-098 約2分10秒を順に)。
- 結果: `D:\codes\sample_test\e2e\test-results\playwright-report.json`(テストごと、idつき)。失敗したテストの証跡(スクリーンショット、録画、トレース、コンソールの記録)は `e2e\test-results\<テストのフォルダ>\` に出る。
- **Playwright は次に実行するときに `test-results` の中を消す。** 実行し直す前に、必ず次のコマンドでテストランのフォルダに取り込む(JSONレポートと証跡がコピーされる)。

```powershell
python "D:\codes\ai_test_management_skills\scripts\tm.py" e2e-results --root "D:\codes\sample_test\テスト成果物" --run <テストランのID> --json "D:\codes\sample_test\e2e\test-results\playwright-report.json"
```

- **メッセージの先頭が `【ブロック】` の失敗は、事前条件が成り立たず判定しなかったもの**(支出なし・取り崩しなし・範囲内などが成り立たない。ローレベルテストケースの共通の決まり)。Playwright と e2e-results では Fail になるので、テスト実行でブロックに直す。
- LTC-096 は、LTC-097・LTC-098 で比べるための結果の欄の内容を `e2e\saved\LTC-096_chrome_結果の欄.json.gz` に保存する(SHA-256 と全文。`test-results` の外なので消されない。LTC-096 を流すたびに上書きする)。LTC-097・LTC-098 の (4) はこれと比べる。保存が無いとき、保存したときとテスト対象の SHA-256 が違うときは (4) を判定せずブロックにする。LTC-096 の証跡にするときは、このファイルをテストランの `証跡/` にコピーする。
- 1件だけ流すとき: `npx playwright test -g "LTC-020"`。LTC-097・LTC-098 だけを流すと、前に保存した LTC-096 の内容と比べる。
- 参考の WebKit(テスト計画の TA-018 の備考。SPEC-061 の確認にはしない): `npx playwright test --config=playwright.webkit.config.js`。結果は `e2e\test-results-webkit\playwright-report.json`。**e2e-results には取り込まない**(取り込むと、WebKit の失敗がローレベルテストケースの Fail になる)。
- 使うブラウザ: Chrome・Edge はインストール済みのもの(channel `chrome`・`msedge`)。Firefox は Playwright の Firefox 159.0(firefox v1572)、WebKit は Playwright の WebKit 27.2(webkit v2388)。
