## BUG-001

- 再現できる手順:
  1. `http://localhost:8000/retirement_simulator.html` を開く。
  2. 給与(年収) 0、開始時貯金 0、開始時投資残高 100,000、現役時生活費(月額) 100,000、投資率(%) 0、利回り(年%) 0 を入れる(ほかは初期値)。突発的な支出が起きないよう、乱数を TD-002 の「支出なし」に差し替える。
  3. 「開始」をクリックする。
- 期待値: すべての月で、投資が0円以上(LTC-055〜LTC-058。持っている以上は取り崩せない。SPEC-037、SPEC-054、COND-041)。
- 実際の結果: 30歳1月に `🔄 投資から補填: ¥100,000 (税金: ¥20,000)` と出て、`投資: ¥-20,000` になる。その後もすべての月で投資が −20,000円 のまま(利回り0%)。開始時投資残高ごとの30歳1月の投資は次のとおりで、どれも0円未満になった。
  - 100,001円(LTC-055): ¥-19,999
  - 100,000円(LTC-056): ¥-20,000
  - 99,999円(LTC-057): ¥-20,000(取り崩し ¥99,999、税金 ¥20,000、現金 ¥-1)
  - 10,000円(LTC-058): ¥-2,000
  - 0円(LTC-059): 取り崩しが起きず、投資は0円のまま(Pass)
  - 同じ結果が Chrome・Edge・Playwright の Firefox で出た(LTC-096〜LTC-098 の (1))。
  - 探索的テスト(SES-001、SES-005、SES-008、SES-013)でも、範囲の内の値だけで同じことが起きた。例: 初期値から退職年齢 60・イベント発生率 0 にすると、77歳4月に `🔄 投資から補填: ¥75,447.784 (税金: ¥15,090)` の後 `現金: ¥-7,552 投資: ¥-15,090`(SES-001)。給与 0・開始時貯金 0・開始時投資残高 160,000・投資率 0・利回り 0・イベント発生率 0 では、不足分 155,600 を払える残高があるのに 30歳1月に `投資: ¥-26,720`(SES-005。残高が「不足分 × 1.2」より少ないと必ず0円未満になる: 186,720 → ¥0、186,719 → ¥-1)。0円未満になった投資は、現金が0円以上に戻っても0円未満のまま残る(SES-005)。
- 原因の見立て(ソースを読んだ推測): 取り崩す額を `Math.min(投資の残高, 不足分)` で決めたうえで、さらにその20%を税金として投資の残高から引いている(`retirement_simulator.html` 145〜147 行)。税金の分だけ、持っている残高より多く引かれる。取り崩しの税金そのものの扱いは Q-010 の回答待ちだが、残高が0円未満になることは回答を待たずに期待値から外れる。
- 続きのセッションで見つけた再現条件: 開始時投資残高 0.35(不足分 0.3 × 1.2 より少ない)で「投資: ¥-0」になる(SES-022 周8)。

  2. 開始時貯金 1,000,000,000、利回り(年%) 0 を入れる(給与(年収)は初期値の 3,000,000、投資率は初期値の 20)。乱数を TD-002 の「支出なし」に差し替える。

- 原因の見立て(ソースを読んだ推測): 給与変更の設定を読むところで `if (age > 0 && salary > 0)` の設定だけを使っている(`retirement_simulator.html` 172 行)ので、年収0円の設定が捨てられる。年収1円の給与変更(LTC-071)は Pass。

## BUG-028

- 再現できる手順:
  1. `http://localhost:8000/retirement_simulator.html` を開き、イベント発生率を 0 にする(ほかは初期値)。
  2. 年金開始年齢の欄の値を選んで、キーボードで `65。5` と打つ(句点。日本語入力のまま「.」を打ったときの文字)。
  3. 「開始」をクリックし、65歳1月の行と、年金の行があるか、100歳12月の総資産を見る。
- 期待値: 打った記号が欄から黙って消えない。消えるなら、そのことが利用者にわかる。ありえない年齢(655歳)が利用者に知らされる、またはそのままでは計算しない(Q-016 の回答待ち)。
- 実際の結果: 欄の値は 655(正しい値の状態)。65歳1月から100歳まで「退職後収入: ¥0」で、年金の行は0件。100歳12月の総資産は ¥-65,097,685(65 なら ¥35,594,188)。注意は無い。退職年齢「60,5」「60、5」「６０。５」は 605 になり、100歳12月まで852か月すべて給与で、年金は0か月(総資産 ¥157,676,511)。年金開始年齢「67,5」は 675、「65・5」は 655。開始年齢「30,5」は 305 で、結果の欄が空になる(BUG-006 と同じ形)。全角の点「．」は小数点として読まれる。
- 証跡: RUN-20261123-091035/証跡/SES-017_01_退職年齢60,5と年金開始年齢65。5が605と655になる.jpg、RUN-20261123-091035/証跡/SES-017_03_設定項目の文字と小数の観察記録.txt
- 探索的テストで見つけた場合は、問題と判断した手がかり: User desires(60.5歳・65.5歳のつもりで打つ)、Purpose(REQ-013)、Product(全角の点「．」は小数点として読まれ、ほかの記号は捨てられる)。
- 重要度: 中(SES-017 の案のとおり)。退職しない・年金がまったく入らないなど結果が大きく変わる。欄には「605」「655」と見えるので、欄を見れば気づける余地はある。
- メモ: BUG-017 と同じ原因(数値の欄が、数として読めない文字を黙って捨てる)かもしれない。年齢の欄に上限が無いので 605歳・655歳をそのまま使う点は BUG-005 と同じ原因かもしれない。Q-016 の回答で却下になりうる。

## BUG-029

- 再現できる手順:
  1. `http://localhost:8000/retirement_simulator.html` を開き、イベント発生率を 0 にする(ほかは初期値)。
  2. 退職年齢の欄をクリックして 65 と打つ。
  3. ポインタを退職年齢の欄の上に置いたまま、マウスホイールを下へ3回回す。
  4. 欄の値を見て、「開始」をクリックする。
- 期待値: ホイールではページがスクロールし、欄の値は変わらない。変わるなら、利用者にわかる。
- 実際の結果: 手順3で退職年齢が 65 → 62 になり、ページはスクロールしない。手順4の結果は62歳から退職後収入、65歳から年金になる。注意の文は無い。開始年齢 100 でホイールを上へ回すと 101 になり、「開始」で結果の欄が空になる(BUG-006 の状態)。給与変更の年齢・年収でも同じで、年齢 1 → 0、年収 1 → 0 になると、その給与変更は丸ごと使われなくなる(ほかに3行がある状態の (1, 6000000) の行で、年齢が 0 になってその行だけが使われないことを確かめた。SES-016)。ポインタが欄の外にあるとき、またはフォーカスが欄に無いときは、ページがスクロールして値は変わらない。
- 証跡: RUN-20261123-091035/証跡/SES-019_02_退職年齢65の欄でホイールを3回下げると62になる.jpg、RUN-20261123-091035/証跡/SES-019_03_年齢の組と入れ方ごとの期間.txt、RUN-20261123-091035/証跡/SES-016_02_給与変更の値の観察記録.txt
- 探索的テストで見つけた場合は、問題と判断した手がかり: User desires(ホイールはページを送る操作で、値を変えるつもりは無い)、Purpose(REQ-013)、CH-004 のリスク(年齢の食い違いに気づける手がかりが無いまま結果を出す)。
- メモ: 候補-SES-016-5 と候補-SES-019-1 を1件にまとめた。数値の入力欄(type="number")にフォーカスがあるときのブラウザ標準の動きを、画面が止めていないものと考えられる(推測。Chromium系の内蔵ブラウザだけで確かめ、Firefox・Safari では確かめていない)。製品の不具合として扱うか、ブラウザの振る舞いとして受け入れるかの判断がいる。欄の数字は変わって見えるので、見れば気づける。
