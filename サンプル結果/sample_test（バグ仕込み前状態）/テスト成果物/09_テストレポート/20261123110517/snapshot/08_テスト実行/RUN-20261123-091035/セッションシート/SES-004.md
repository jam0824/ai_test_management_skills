## テストチャーター

CH-007: 給与変更の年齢・年収を、負の値・整数でない年齢・数字でない文字で探索し、利用者に知らされるか、設定が黙って使われなくなるかを見つける。対象の領域は給与変更設定と「開始」、結果の表示。時間枠15分。リスク: 入れた設定が使われなかったことに利用者が気づける手がかりが何も無いまま、結果を出す。給与変更の年収 −1円(CI-128)もここで見る。合否の基準は Q-016 の回答待ち。

前のセッションでわかっていること: 設定項目の欄は、空欄・数として読めない文字(badInput)を0として計算する(SES-001、SES-003)。給与変更の設定は、基本の給与が空欄でも使われる(SES-001 のテストメモ 19)。

## テストメモ

1. 給与変更設定を表示し、「➕ 給与変更を追加」で1つ追加して、何も入れずに「開始」(イベント発生率0)→ 欄には灰色の「35」「4000000」(placeholder)が見えるが、値は空。結果の給与は30歳1月〜64歳12月の420か月すべて「¥188,125」で、`[年収: …]` の行は無い。注意なし(証跡 SES-004_01) → 空の給与変更は黙って使われない。灰色の例の値を入力済みと取り違えると、「35歳から400万円」が使われていないことに気づけない(placeholder の色は値より薄いので、見分ける手がかりはある)。欄の属性: 年齢は `min=0 max=100`、年収は `min=0`(上限なし)
2. 給与変更 (年齢 -5, 年収 5000000) → 年齢の欄は不正(rangeUnderflow)。結果は420か月すべて「給与: ¥188,125」で `[年収: …]` の行が無い = **給与変更が黙って使われない**。注意なし → 負の年齢の設定は捨てられる。範囲の内の0ではどうかを見る
3. 給与変更の年齢 0(欄は正しい値の状態)→ これも420か月すべて「¥188,125」で、**使われない**(証跡 SES-004_02)。年齢 1・29・30 にすると、30歳1月から420か月すべて「給与: ¥298,458 (投資: ¥59,692) [年収: ¥5,000,000]」と使われる → 開始年齢より前の年齢(1・29)は「開始から使う」扱いなのに、0 だけは使われない。欄の `min=0` で0は正しい値とされているので、0を入れた人は設定が効かないことに気づけない(Q-012 の「開始年齢より前の年齢」の回答とは別に、0 と 1 で扱いが違うことが問題)
4. 給与変更の年齢 40.5 → 欄は不正(stepMismatch)。「¥188,125」が132か月(30〜40歳)、41歳1月から288か月「¥298,458 [年収: ¥5,000,000]」 → 整数でない年齢は、その値以上になる最初の年齢(41)から使われる(SES-003 の退職・年金開始と同じ形)。注意なし
5. 給与変更 (40歳, 年収 -1)(CI-128)→ 欄は不正(rangeUnderflow)。420か月すべて「¥188,125」で、**給与変更が黙って使われない**。-4000000 も同じ。注意なし → 負の年収の設定は捨てられる
6. 比べるために範囲の内の年収 0(SPEC-041・HTC-061 では「40歳から給与0円」で計算されるはず)→ **これも420か月すべて「¥188,125」で、使われない**。40歳1月も「給与: ¥188,125 (投資: ¥37,625)」(証跡 SES-004_03)。年収 0.5(欄は不正)は 40歳1月から「給与: ¥0 [年収: ¥0.5]」と使われる → 年収0円(休職など)の給与変更は、仕様では使われるはずなのに黙って捨てられる。年齢0(3)と同じく、「0」だけが設定なしとして扱われているように見える(推測。0.5 や 1 は使われる)。注意なし。HTC-061(E2E自動テスト)で同じことが見つかる可能性がある
7. 年収 5000000 で、年齢 101(`max=100` を超えるので欄は不正)→ 使われない(計算は100歳12月までなので、使われないこと自体は当然とも読める)。年齢「abc」→ 1文字も入らず空、使われない。年齢「4e」→ 欄に「4e」と見えたまま値は空(badInput)、使われない。年齢40・年収「abc」→ 空、使われない。どれも注意なし → 年齢・年収のどちらかが空・数として読めない・負・0 のとき、その給与変更は丸ごと捨てられる。欄に「4e」が見えていても捨てられる
8. 給与変更を2つにした: (35歳, -1) と (45歳, 6000000) → 30〜44歳の180か月は「¥188,125」(基本の年収)、45歳1月から240か月「¥348,625 [年収: ¥6,000,000]」。1つ目を (35歳, 0) にしても同じ(証跡 SES-004_04) → 捨てられるのは不正な1つだけで、ほかの給与変更は使われる。「35歳から休職(年収0円)、45歳で復職」という使い方をすると、休職の10年分が基本の年収のまま計算され、結果からは休職が効いていないことに気づきにくい(35歳1月の行は「給与: ¥188,125」で、30〜34歳と見た目が同じ)
9. 「0 は設定なしと扱われる」という推測を確かめた: 開始年齢 0、給与変更 (0歳, 5000000) → 0歳1月から780か月すべて「¥188,125」で、使われない。同じ条件で年齢 1 → 0歳の12か月は「¥188,125」、1歳1月から768か月「¥298,458 [年収: ¥5,000,000]」 → 開始年齢と同じ0歳を指定しても、0 だけは使われない。開始年齢より前かどうかではなく、値が0であることで捨てられている(年収0も同じ。6)
10. 年齢「0.0」(欄は正しい値の状態)→ 使われない。年齢「0.1」(欄は不正)→ 30歳1月から420か月「¥298,458 [年収: ¥5,000,000]」と使われる → 数として0になる値だけが捨てられ、0にわずかでも足すと使われる(9 の推測と合う)
11. (チャーター外。範囲の内の値)給与変更を逆の順に入れた: (50歳, 6000000) → (40歳, 5000000) → 30〜39歳「¥188,125」120か月、40歳1月から「[年収: ¥5,000,000]」120か月、50歳1月から「[年収: ¥6,000,000]」180か月 → 追加した順ではなく年齢の順に使われる。黙って使われない形は無かった(Q-012 の回答で基準が変わりうる)
12. ネットワーク要求の記録(自分のタブ、SES-001 から通して37件)→ すべて `GET http://localhost:8000/retirement_simulator.html → 200`。**外部への要求は0件**。コンソールは画面を開くたびの既知のエラー2つ×37回だけ。確かめた後、自分のタブ(tab-4)を閉じた
- 思いついたアイデア・リスク:
  - 給与変更は、年齢・年収のどちらかが「0・負・空・数として読めない」と、その1件が丸ごと捨てられる。捨てられたことは、結果に `[年収: …]` の行が無いことでしかわからない
  - 年収0円の給与変更(休職・無職の期間)は README の使い方として自然だが、黙って使われない。仕様(SPEC-041)と食い違う
  - 整数でない年齢・小数の年収(0.5円)は使われる。年収 0.5 では「¥0 [年収: ¥0.5]」と円の小数が表示される
