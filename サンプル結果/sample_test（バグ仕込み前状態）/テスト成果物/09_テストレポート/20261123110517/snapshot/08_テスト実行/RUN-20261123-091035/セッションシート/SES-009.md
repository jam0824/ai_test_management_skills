## 課題
- ほかのセッションの候補と重なるもの: 候補-SES-009-2(給与変更の空の欄の placeholder)は 候補-SES-012-2 と同じ振る舞いの見込み。テストメモ5・33 の Enter で実行されないことは 候補-SES-015-3 と、テストメモ25 の aria-live が無いことは 候補-SES-015-2 と重なる
- 次の振る舞いは、比べる流れで迷うところとして見つけたが、不具合とするかが質問の回答待ちなので、候補にしていない: (1) 給与変更設定を非表示にしても、入れた給与変更が計算に使われる(テストメモ7。Q-020 (3)、CH-013)(2) 同じ条件でも実行のたびに結果が変わり、条件の違いによる差と区別できない(テストメモ6。Q-020 (2)、CH-012)(3) 年金開始年齢 65 のまま退職年齢 70 にすると、年金は70歳から入り、欄の値と食い違う。年金開始年齢を 60 / 65 / 70 と変えて比べても結果は同じ(テストメモ8・32。Q-002)(4) 退職年齢より後の給与変更は黙って使われない(テストメモ15。Q-012)
- README の使用例は、ケースごとに書かれていない欄(ケース3の年金月額など)があり、画面を開き直さずに続けて入れると、前のケースの値が残って結果が変わる(テストメモ22)。使用例の条件の書き方の問題で、テスト対象の不具合とは言えない
- 内蔵ブラウザで、自分のタブが前面に無いときは画面が描かれず、クリック・キー入力・スクリーンショットができない(テストメモ7〜26。27で開き直したら描かれるようになった)。テストメモ1〜7と、27以降の画面での確認(27・28・29・33・34・36・37)はクリックとキーで操作し、8〜26とそのほかは値の入力とボタンを JavaScript にした。スクロールの手間(テストメモ23・30 の行の位置・ホイールの目盛り数)は、要素の位置と行の数から計算したもの
- 比べる別の流れとして「別のタブで同じ画面を開いて並べる」は、自分のタブ以外を使わない決まりなので試していない
