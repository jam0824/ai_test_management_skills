SES-016 (CH-007) 給与変更の値の観察記録
テスト対象: http://localhost:8000/retirement_simulator.html / Claude の内蔵ブラウザ(Chromium系) / 自分のタブ tab-7
条件: イベント発生率 0、ほかは初期値(開始30歳・退職65歳・給与 3,000,000)。値はキーボードで打った。
「欄」は [年齢の値, 年齢の欄が正しい値か, 年収の値, 年収の欄が正しい値か](JavaScript で読んだ)。
「給与の行」は、結果の欄の給与の行を同じ額が続くまとまりにしたもの(最初の月 額 [年収] x 月数)。

1. 誤りを順に直す流れ
 (-5, 5000000)          欄 [-5,false,5000000,true]   給与の行 30歳1月 ¥188,125 x420           (捨てられる)
 年齢を 40 に直す        欄 [40,true,5000000,true]    30歳1月 ¥188,125 x120 / 40歳1月 ¥298,458 [年収: ¥5,000,000] x300
 年収を -1 にする        欄 [40,true,-1,false]        30歳1月 ¥188,125 x420                     (捨てられる)
 年収を 6000000 に直す   欄 [40,true,6000000,true]    30歳1月 ¥188,125 x120 / 40歳1月 ¥348,625 [年収: ¥6,000,000] x300
 → 直した後は、前の誤りの影響を残さずに使われる

2. 0 の近くの値
 年齢 "-0"(欄は正しい値)        → 捨てられる(年齢0と同じ)
 年齢 "-0.5"(rangeUnderflow)    → 捨てられる
 年齢 "4e1"(欄に 4e1 と見える)   → 40歳1月から使われる
 年齢 "39.999"(stepMismatch)    → 40歳1月から使われる
 年収 "1e-7"(stepMismatch)      → 40歳1月から「給与: ¥0 (投資: ¥0) [年収: ¥0]」x300
 年収 "0.0001"                  → 40歳1月から「給与: ¥0 (投資: ¥0) [年収: ¥0]」x300
 年収 "1e-400"(値は 0 に丸まる) → 捨てられる
 年収 "-0"(欄は正しい値)        → 捨てられる
 (40, 0.0001) と (50, 0) の2行  → 40歳1月から100歳まで「[年収: ¥0]」が続き、50歳1月も「給与: ¥0 (投資: ¥0) [年収: ¥0]」。50歳の 0 の行は捨てられている
   → 結果には「[年収: ¥0]」と出るのに、年収に 0 と入れた行は使われない

3. 2行以上の組み合わせ
 (40, -1) と (40, 5000000)            → 40歳1月から [年収: ¥5,000,000]
 (40, 8000000) と (40, -5000000)      → 40歳1月から [年収: ¥8,000,000]
 (40, 8000000) と (50, -1000000)      → 40歳1月から [年収: ¥8,000,000] が 300か月(64歳12月まで)。100歳12月の総資産 ¥269,065,000
 (40, 8000000) と (50, 7000000)       → 50歳1月から [年収: ¥7,000,000] 180か月。100歳12月の総資産 ¥251,947,076
   → 減額のつもりの負の年収は捨てられ、前の年収が続く。結果の 50歳1月の行は「[年収: ¥8,000,000]」で、捨てられたことはわからない
 (50, -1) (40, 6000000) (45, 空。灰色の 4000000 が見える) (55, 4000000) の4行
                                       → 40歳1月 [年収: ¥6,000,000] x180 / 55歳1月 [年収: ¥4,000,000] x120。-1 の行と空の行は捨てられる(画面: SES-016_01)
 (40.5, 5000000) と (41, 7000000)     → 30歳1月 ¥188,125 x132 / 41歳1月 [年収: ¥7,000,000] x276。40.5 の行の年収は一度も出ない

4. 退職年齢との境目
 (64.5, 4000000)(退職65)              → 使われない(65歳からとして扱われ、65歳からは給与が無い)
 (64, 4000000)                         → 64歳1月から [年収: ¥4,000,000] x12

5. ほかの欄との組み合わせ
 開始年齢 30.5 と (40, 5000000)       → 30.5歳1月 x120 / 40.5歳1月 [年収: ¥5,000,000] x300
 開始年齢 30.5 と (0.5, 5000000)      → 30.5歳1月から [年収: ¥5,000,000] x420
 開始年齢 0 と (0.5, 5000000)         → 0歳1月 ¥188,125 x12 / 1歳1月 [年収: ¥5,000,000]
 開始年齢 100・退職 101 と複数行      → 100歳1月から、100以下で最後の (55, 4000000) が使われる
 退職 101 と (100, 7000000)           → 100歳1月 [年収: ¥7,000,000] x12。(99.5, 7000000) も同じ

6. 矢印キーとマウスホイール
 年収 -1 の欄で上矢印 → 0(欄は正しい値になる)。年齢 -5 で上矢印 → 0、もう一度 → 1
 年齢 50.5 で下矢印 → 50。40.5 で上矢印 → 41
 年齢 1 の欄にフォーカスがあり、ポインタがその欄の上にある状態でホイールを1目盛り下へ → 0。ページはスクロールしない(scrollY は変わらず)
   → 「開始」すると、その給与変更は捨てられる(30歳1月 ¥188,125 x408 / 64歳1月 [年収: ¥4,000,000] x12)
 年収 1 の欄で同じ操作 → 0、「開始」すると 50歳の行が捨てられる
 年齢 0.5 の欄で同じ操作 → 0
 ポインタが欄の外にあるときは、ホイールでページがスクロールし、値は変わらない
 (チャーター外)退職年齢の欄でも同じ: 65 → 64(ホイール下)→ 65(ホイール上)

7. そのほか
 年収 "500万"     → 欄は 500。40歳1月から「給与: ¥36 [年収: ¥500]」
 年収 "ー300000"(長音記号) → 欄は -300000(rangeUnderflow)。捨てられる
 年齢 "５５"(全角) → 55
 年齢 "0050"      → 50 として使われる
 年収 "5000000.5" → 「[年収: ¥5,000,000.5]」と円の小数が出る
 マイナスに似た記号(4行のうち4行目の年齢、3行目の年収を変えた)
   年齢 "−5"(数学のマイナス U+2212) → 欄の値は 5(正しい値)。30歳1月から「[年収: ¥4,000,000]」x120 と、開始から使われる
   年齢 "－5"(全角のマイナス U+FF0D) → 欄の値は -5(rangeUnderflow)。捨てられる(30歳1月 ¥188,125)
   年収 "−1000000"(数学のマイナス)  → 欄の値は 1000000。50歳1月から「給与: ¥66,917 [年収: ¥1,000,000]」x180
   → 同じ「マイナス5」のつもりでも、記号によって「捨てられる」と「正の値として使われる」に分かれる
 給与変更の欄で Enter → 実行されない(結果は変わらない)
 行を追加しても、表示/非表示を切り替えても、ほかの行の値は残る

ネットワーク要求(tab-7): GET http://localhost:8000/retirement_simulator.html → 200 の1件だけ。外部への要求は0件
コンソールのエラー: 画面を開いたときの既知の gap income line / gap expense line の2つだけ
