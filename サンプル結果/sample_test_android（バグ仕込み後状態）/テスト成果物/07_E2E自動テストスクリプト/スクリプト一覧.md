# E2E自動テストスクリプト

入力: `06_テスト実装/ローレベルテストケース.md`(実施方法がE2E自動テストの72件)、`テストデータ/*.json`(TD-001〜009)、`テスト環境.md`、`テストスイート.md`。

## 道具

- **Python 3.11 + adb**(新しく入れたものは無い。Playwright・Appium・uiautomator2 は使わない)。スクリプトは `e2e/` に置いた。
- 操作は `テスト環境.md` の「操作のしかた」のとおり: 部品は uiautomator dump の resource-id で探し、`input tap / text / keyevent / keycombination / swipe` で利用者と同じように画面から入力・開始・スクロール・回転する。結果は `outputLine` の文字を画面の並び順に読み、`テスト環境.md`「結果の1行の読み取り方」で月の記録に分ける(`e2e/framework/records.py`)。
- 入力欄を消すときは、Ctrl+A → 消す のあとに、カーソルを末尾に動かして文字数分だけ消す。欄を続けて押すと Ctrl+A が効かず末尾の1文字しか消えないことがあったため(入力のあとは毎回 dump で値を確かめ、違えば入れ直す)。
- 端末は `emulator-5554` に固定してある(`e2e/framework/device.py`。変える引数は無い)。gradle の connected 系タスクは使わない。
- 始めに読み取り用の表示(`wm size 1080x6000`、`wm density 160`)・自動回転オフ・縦向きにし、終わったら標準の表示(`wm size reset`、`wm density reset`)・自動回転オン・機内モードオフに戻す。
- テストデータは `テスト成果物/06_テスト実装/テストデータ/*.json` を読み込む(スクリプトに値を埋め込んでいない)。期待値はローレベルテストケースの期待値をそのまま判定にした。

## 実行のしかた

前もって: エミュレータ emulator-5554 を起動し、デバッグ版 APK を入れておく(`./gradlew assembleDebug` → `adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk`)。

```bash
# 全件(テストスイートの順番)。結果と証跡をテストランのフォルダに直接書く
python -X utf8 e2e/run_e2e.py --suite "テスト成果物/06_テスト実装/テストスイート.md" --out "テスト成果物/08_テスト実行/<RUN-ID>/証跡/E2E"
python "<プラグイン>/scripts/tm.py" e2e-results --run <RUN-ID> --json "テスト成果物/08_テスト実行/<RUN-ID>/証跡/E2E/report.json"

# 一部だけ
python -X utf8 e2e/run_e2e.py --only LTC-001,LTC-011
# 一覧
python -X utf8 e2e/run_e2e.py --list
```

| もの | 場所 |
|---|---|
| 結果(Playwright の JSON レポートの形) | `<--out>/report.json`(既定の `--out` は `e2e/test-results`)。テスト名の先頭がローレベルテストケースのid。Fail のメッセージの先頭は「期待値と違う(n 件): …」か「スクリプトが途中で止まった: …」 |
| 証跡 | `<--out>/evidence/<LTC-ID>/`: `判定.txt`(確かめた期待値ごとの OK/NG と読んだ値)、`runN_<名前>_lines.txt`(読み取った結果の行。画面の並び順のまま)、`runN_<名前>_dump_first.xml` / `_dump_last.xml`(読み始めと読み終わりの dump)、`end.png` / `end_dump.xml`(テストの終わりの screencap と dump)。ほかに、テストによって回転の前後などの dump がある。`--save-all-dumps` でスクロールのたびの dump もすべて残す |

- `--out` のフォルダの `evidence/<LTC-ID>/` は、同じidを流し直すと消して作り直す。前の実行の証跡を残すときは、テストランごとに `--out` を変える(上の例のようにテストランのフォルダの中にする)。`tm.py e2e-results` は Fail のテストの証跡だけをコピーするので、Pass の証跡はこの `evidence/` に残る。
- 途中で止めても、そこまでの `report.json` は残る(1件終わるたびに書く)。
- 「同じ実行を使ってよい」と書かれた組(LTC-005・011・012、016〜019・024、025〜028、039・041、056・057、LTC-039・040 が使う LTC-011 の実行)は、1回の実行の中で結果を使い回す。使い回したテストの `判定.txt` にそう書き、読み取った行のコピー(`共有_…_lines.txt`)を置く。1件だけ流したときは、そのテストの中で実行する。
- 終わると `Pass n 件 / Fail n 件` を出す。Fail が1件でもあれば終了コードは1。

見込み時間: 全72件で約3〜3.5時間(動作確認で測った時間から見積もった。開始55歳で最後の行まで読む実行が約1分45秒(入力と読み取りで約80秒)、開始30歳で約2分30秒、横向きで最後の行まで読むと約8〜9分。横向きで読む LTC-062・064・065 だけで約35分かかる)。
