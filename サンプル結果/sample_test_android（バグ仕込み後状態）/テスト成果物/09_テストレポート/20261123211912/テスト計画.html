テスト計画

テスト目的

老後資金シミュレーター(Android版)が、利用者が自分の条件を入力して老後までの資金の推移を確かめ、老後資金が足りるかの目安を判断する(REQ-001)のに使えるかを、システムテストで確かめる。
特に、手取り・期間の切り替わり・投資と取り崩しの計算(REQ-003〜REQ-005)と、正しくない入力のときに誤った結果に気づかず使うことが無いか(REQ-011)を重点に確かめる。リスク分析で「高」とした9件(RISK-001、002、005、007、010、011、012、028、029)はすべてテストする。
結果は、テストを依頼した人に、要求・仕様・リスクごとにどこまで確かめたか、どこが質問の回答待ちで確かめられていないかを示す。

計算式の多くは質問(Q-001〜Q-025)の回答待ちで、1円単位の期待値は決められない。そこで、期待値を推測で決めず、テストベースから決まる性質で確かめるアプローチをとる。性質の例:

  • 初期値: 起動直後の入力欄が仕様書の初期値と同じ(SPEC-004〜SPEC-018)
  • 極端値: 投資率0%・開始時投資残高0円なら投資残高は増えない、イベント発生率0%ならイベントは1回も起きない、100%なら毎月起きる(SPEC-040 の確率の定義から決まる)
  • 関係: 総資産 = 現金 + 投資(SPEC-046 の読み取り)、手取りは差し引いたものなので月の給与収入は年収÷12 を超えない(SPEC-025)、年収を増やすと月の給与収入は減らない、利回りを上げると投資残高は減らない
  • 期間による使い分け: 現役・退職後・年金受給の各期間で、表示される収入と生活費が、その期間の入力値に対応して変わる(SPEC-021〜SPEC-024)。切り替わる月の境界そのものは Q-002 の回答待ち
  • 異常にならないこと: 資金が尽きても計算と表示が続き、NaN や読めない値が出ない。投資残高があるあいだは、現金の不足が投資の取り崩しで補われる(SPEC-032)

1円単位の期待値や、境界の月の期待結果が要るテストは、回答待ちとして質問のIDを付けて残す。

対象外/制約

対象外

対象外にするもの理由残るリスク
Android 8.0(API 26)〜13(API 33)での動作(SPEC-057 の一部)API 26 の端末・エミュレータが用意されておらず、使える環境は emulator-5554(API 34)だけ。API 34 で動くことは、ほかのすべてのテストで間接的に確かめるRISK-039(中)が残る。新しい API の使用で古い版だけ落ちる不具合は見つけられない
注意事項(目安であること、制度変更を考慮しないこと)を画面に出すこと(RISK-040、低)画面に出す必要があるかが決まっていない(Q-026 の回答待ち)。テストベースから期待結果が決まらないRISK-040(低)が残る。探索的テストの途中で、注意事項の文が画面にあるかは記録だけしておく
性能テスト(開始してから結果が出るまでの時間など)時間の基準がテストベースに無い。結果がスクロールで見られること(RISK-035)は機能テストで確かめ、極端に遅いと感じたときは探索的テストで記録する応答時間の劣化は基準が無いため判定しない
ユニットテスト、プロジェクトに既にある自動テスト(testDebugUnitTest、connectedDebugAndroidTest)今回作る自動テストはE2E自動テストだけ。既存のテストは開発者のもので、テストベースから作ったものではないなし(結果はテストの根拠に使わない)
1円単位の計算結果、期間が切り替わる境界の月の期待結果、イベントの金額計算式・境界・金額が質問(Q-002、Q-004〜Q-009、Q-012〜Q-014、Q-018、Q-021、Q-022、Q-025)の回答待ち。推測した期待値で Pass にしても何も確かめたことにならないRISK-001、002、004、005、010、011、015 は性質で確かめる範囲しか確かめられない。例えば税率表の誤りは、手取りが年収÷12 を超えず年収に対して減らない範囲なら見つけられない。回答が来たら、テスト分析から見直す

制約

  • テスト環境は Android エミュレータ emulator-5554(Android 14 / API 34)だけ。PC に繋がっている実機 46211JEKB11275 は使わない(adb は -s emulator-5554 か ANDROID_SERIAL で必ず端末を指定する)。
  • ビルドは gradlew assembleDebug(JDK は JAVA_HOME の Android Studio 付属 JDK 21)、インストールは adb install -r。
  • E2E自動テストは、エミュレータ上で画面を利用者と同じように操作する手段(UI Automator、adb)で作る。部品は README.md の resource-id で特定する。結果の行は画面に入った分しか作られないので、先の行はスクロールして読む。
  • 手動テストと探索的テストは、エージェントが adb(uiautomator dump、input tap / input text、screencap)でエミュレータを操作して行う。証跡は screencap の画像と uiautomator dump の XML で残す。
  • 期待値はテストベースから決める。テスト対象のソースコードから期待値を写さない。
  • 質問 Q-001〜Q-027 はすべて未回答で、回答待ちのまま最後まで進める。回答待ちのテストは実装も実行もされず、テストレポートで回答待ちとして示す。
  • ランダムイベントは乱数を固定する方法がわからない(Q-020)。イベント以外の計算を確かめるテストは、イベント発生率を0%にして行う。
