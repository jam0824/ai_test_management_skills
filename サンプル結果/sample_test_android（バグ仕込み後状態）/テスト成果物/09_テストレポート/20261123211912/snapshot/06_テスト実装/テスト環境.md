## 起動のしかた

```bash
./gradlew assembleDebug
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 shell am force-stop jp.sample.retirementsimulator   # 起動し直すとき
adb -s emulator-5554 shell am start -n jp.sample.retirementsimulator/.MainActivity
```

Git Bash から `/sdcard/...` などのパスを adb に渡すときは `MSYS_NO_PATHCONV=1` を付ける(付けないと `C:/Program Files/Git/sdcard/...` に変えられて失敗した)。

## 表示の2つの設定

| 名前 | 設定 | 使うテスト |
|---|---|---|
| 標準の表示 | `adb -s emulator-5554 shell wm size reset`、`adb -s emulator-5554 shell wm density reset`(1080x2220、密度 440) | 手動テスト(LTC-066〜068、072〜075)、探索的テスト |
| 読み取り用の表示 | `adb -s emulator-5554 shell wm size 1080x6000`、`adb -s emulator-5554 shell wm density 160` | E2E自動テスト |

読み取り用の表示は、結果を全行読む実行が多い(年収のはしご25段など)ため、1回の uiautomator dump で読める行を増やして実行時間を減らすためのもの。入力欄14項目と「開始」が1画面に収まり、1回の dump で約190行の `outputLine` が読める。人が見た目を判断するテスト(文字の切れ・重なり)はこの表示では行わない。表示を変えたら、アプリを起動し直してから使う。テストがすべて終わったら標準の表示に戻す。

## 操作のしかた

- **部品の特定**: `uiautomator dump` の XML の resource-id(README.md の表のとおり。testTag が resource-id として見える)。
- **入力**: 入力欄の中心をタップ → `input keycombination 113 29`(Ctrl+A)→ `input keyevent 67`(消す)→ `input text <値>` → `input keyevent 4`(キーボードを閉じる)。入力のたびに dump を取り直す(キーボードが出ると部品の位置が変わるため。古い位置のまま次の欄を押したら、別の欄に入った)。
- **給与変更の枠**: 起動直後は `salaryChanges` が無かった(非表示)。`toggleSalaryChanges` を1回押すと出る。追加した行の `salaryChangeAge`・`salaryChangeSalary` は空欄で出る。行は上から順に並ぶ。
- **スクロール**: 結果を読むときは、ゆっくりした引きずり(読み取り用の表示で `input swipe 540 5000 540 800 3000`、約4200px を3秒)を使う。速い引きずりや長すぎる引きずりは慣性で行が飛び、月の抜けが出た(下のスモークテスト)。手動テストで速く最後の行まで行くときは、標準の表示で `input swipe 540 1900 540 300 100` を繰り返す。
- **向き**: `settings put system accelerometer_rotation 0` のあと、`settings put system user_rotation 1`(横)/ `0`(縦)。終わったら `accelerometer_rotation 1` に戻す。
- **機内モード**: `cmd connectivity airplane-mode enable` / `disable`。状態は `cmd connectivity airplane-mode` で見る。
- **権限・通信量**: `dumpsys package jp.sample.retirementsimulator`(requested permissions、uid)、`dumpsys netstats` の `mAppUidStatsMap:` の表(`uid rxBytes rxPackets txBytes txPackets`)。
- **証跡**: `exec-out screencap -p > <名前>.png`、`uiautomator dump /sdcard/d.xml` → `pull`。

## 結果の1行の読み取り方

結果の書式は Q-021 の回答待ちなので、テスト設計の決めたとおり、画面の表示から読み取り方を決めた(期待値ではなく、どの語がどの項目かの決め方)。結果は1か月が複数の `outputLine` に分かれて出る。

| 行の形(見た例) | 読み取る項目 |
|---|---|
| `-- 30歳5月 --` | 月の記録の見出し。年齢と月(1〜12)。次の見出しの前までの行がこの月の記録 |
| `給与: ¥188,125 (投資: ¥37,625)` | 収入(収入の種類 = 給与)。`(投資: ¥…)` はその月に投資に回した額。年収が変わったあとは後ろに `[年収: ¥5,000,000]` が付く |
| `退職後収入: ¥50,000` | 収入(収入の種類 = 退職後収入) |
| `年金: ¥145,000` | 収入(収入の種類 = 年金) |
| `生活費: ¥155,600` | 生活費 |
| `▶ 家電故障: ¥100,000` | イベント(名前と金額)。`▶` で始まる行 |
| `🔄 投資から補填: ¥83,000 (税金: ¥16,600)` | 取り崩しの情報(判定には使わない) |
| `現金: ¥974,500 投資: ¥188,125 総資産: ¥1,162,625` | 現金・投資・総資産。マイナスは `¥-5,995,268` の形 |
| `== 60歳 1月: 投資利息 ==`、`投資: ¥2,445,469.636 → ¥2,543,288` | 利息の情報。見出しの前の月の記録の後ろに出る。投資の残高は `現金:` の行から読む(この行の `投資:` と取り違えない) |

金額は `¥` の後の符号つきの数字からカンマを除いて読む。読めない値(NaN、Infinity、空、指数表記、数字以外)はこの形に合わないものとして見つける。押し直しで前の結果が残る場合に備え、行は画面の並び順のまま記録し、同じ見出しが2回出ても別の月の記録として数える(スクロールの重なりは、画面上の位置で取り除く)。
