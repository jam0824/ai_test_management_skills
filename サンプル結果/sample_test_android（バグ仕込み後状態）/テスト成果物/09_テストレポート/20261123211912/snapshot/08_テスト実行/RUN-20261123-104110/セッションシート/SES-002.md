## テストチャーター

CH-001: 設定項目の14入力欄を、空欄・数字以外(文字・記号・全角数字)・小数の入力で探索し、アプリが落ちて入力が失われる所や、おかしな値がエラーの表示なしに結果に出る所を見つける。対象: 設定項目の入力欄、開始、結果の表示。期待するふるまいは Q-010、Q-011 の回答待ちなので、エラーの表示のしかたは記録だけする。

## 使ったテストデータ

TD-011 の 空欄・数字以外・小数 から: `""`、`abc`、`1e5`、`1,000,000`、`-`、`30.5`、`0.1`、`3000000.99`、`1.5.5`、`5 5`(空白入り)。加えて JavaScript の parseFloat と同じ読み方をするという README の記述から、`Infinity`、`-Infinity`。証跡は `SES-002/`。

## テストメモ

1. startAge を空欄で開始 → エラーは出ず、`-- 0歳1月 --` から給与のある結果が出る(0歳で給与と現役時生活費)。空欄は 0 として計算される(README の Android 版の説明「数として読めない欄は0として扱う」と一致)→ 文字を入れたらどうなるか。
2. salary に `abc`(eventProb 0)→ エラーは出ず `給与: ¥0` で計算される。比べるため `1e5` を入れると年収10万円として計算される(¥7,167)。指数表記が通る → 区切りの記号を試す。
3. initialCash に `1,000,000`(お金の入力で自然な書き方)、investRate に `-` → initialCash は 1 円として計算され、30歳1月の現金が ¥32,526 になる。エラーも警告も無い。investRate の `-` は 0%。入力欄の数字キーボードに「,」キーがあり(証跡/環境/アプリANR_再起動後_1524.png の画像で確認)、利用者が普通に打てる → BUG-008。回転で入力が消えるかを見る。
4. startAge に `abc`、salary に `3000000.99` を入れて横向き → 縦向き → どちらも値が残る。開始すると `-- 0歳1月 --` から始まる(abc は 0 歳)。小数の年収は手取りが 3000000 と同じ ¥188,125 → 読めない値の極端な形を試す。
5. salary に `Infinity` → `給与: ¥NaN (投資: ¥NaN)`、`現金: ¥NaN 投資: ¥NaN 総資産: ¥NaN` がエラーの表示なしに全部の月に出る → BUG-009。年齢側も試す。
6. startAge に `-Infinity` → 開始を押した直後にアプリが応答しなくなり、ANR のダイアログ(`老後資金シミュレーター isn't responding`)。CPU 100%のまま、メモリが 173MB → 195MB と増え続けた(40秒)。「Close app」で閉じて起動し直すと、入れていた入力はすべて初期値に戻った(入力が失われる)→ BUG-010。有限の大きな負の値は CH-002 の範囲なので、そちらで試す。
7. startAge `0.1`、retirementAge 空欄、interest `abc`、eventProb `0.5` → 年齢が `9.1歳4月` のように小数で表示される。退職年齢 0 として扱われ、0.1歳から退職後の扱い(退職後収入 ¥0、生活費 ¥228,000)で現金が −2,400万円まで減っていく。エラーは無い。
8. startAge `5 5`(空白入り)、expenseCurrent `1.5.5` → startAge は 5、生活費は `¥1.5` と表示される。最初の数として読める部分だけ使われ、残りは知らせずに捨てられる。円未満の生活費がそのまま表示される。
9. 残りの6欄に、pensionStartAge `abc`、gapIncome `,`、monthlyPension 空欄、initialInv `abc`、expenseGap `-`、expenseRetired `.` を入れ(startAge 64、eventProb 0)開始 → エラーは無く、64歳の行は通常どおり出た。どれも 0 として扱われると考える(推測。65歳以降の行は読んでいない)。

アイデア・リスク:
- 全角数字(`１２３`)は adb の `input text` で入れられず、試せなかった(下の Obstacles)。
- 入力欄に、読めない部分があることを知らせる表示がどの欄にも無い。Q-010・Q-011 の回答待ちなので、知らせ方そのものは不具合にしていない。

## 不具合

- BUG-008(新規): カンマ区切りの金額(`1,000,000`)が先頭の数字(1円)だけで計算される。手がかり: User desires(金額をカンマ区切りで打つのは自然で、数字キーボードにも「,」がある)、Purpose(老後資金の見積もりが大きく誤り、気づきにくい)。
- BUG-009(新規): `Infinity` を入れると結果に `¥NaN` が並ぶ。手がかり: Claims(チャーターの「NaN などの読めない値がエラーの表示なしに出る」に当たる)、Product(ほかの金額は数字で表示される)。
- BUG-010(新規): startAge に `-Infinity` を入れて開始すると、アプリが応答しなくなり、閉じると入力が失われる。手がかり: Purpose / User desires(入力しただけでアプリが止まり、入力を失う)。

## 課題

- 空欄・文字・記号を 0 として、小数・空白・区切りの入った値を先頭の数として、エラーを出さずに計算する。どの値を受け付けるべきか(Q-010)と、正しくない入力のときにどうふるまうべきか(Q-011)の回答が要る。今は利用者が気づかないまま、0歳からの結果や1円の貯金で計算された結果を見ることになる。
- 年齢に小数が入ると `30.5歳1月` のような表示になる(Q-010)。

## PROOF

- Past(何をしたか): 14欄すべてに(最後の6欄は1回の開始でまとめて)、空欄・文字・記号・指数表記・カンマ・空白・小数・Infinity を入れて開始し、1件は回転も行った。
- Results(何がわかり、何を達成したか): どの正しくない入力でもエラーの表示は無く、0 か先頭の数として計算された。カンマ区切りの金額が1円になる(BUG-008)、`Infinity` で NaN が並ぶ(BUG-009)、`-Infinity` でアプリが止まり入力が失われる(BUG-010)を見つけた。回転では正しくない入力も残った。
- Obstacles(よいテストの妨げになったこと): 全角数字は adb の `input text` で入れられなかった。標準の表示で結果の行を上までスクロールで戻すのに時間がかかった(結果の行の一覧が入れ子のスクロールで、速い引きずりで戻らない)。
- Outlook(まだ何をする必要があるか): 最後の6欄は、結果の行を65歳以降まで読んで効き方を確かめていない。全角数字(クリップボード経由などで入れる方法を用意して)。Q-010・Q-011 の回答が来たら、エラーの表示を確かめるセッション。
- Feelings(この結果にどれくらい自信があり、何が気になっているか): 正しくない値を黙って 0 や先頭の数にするふるまいは、どの欄でも同じ読み方(parseFloat)なので、残りの欄も同じと考える(最後の6欄は開始して落ちないことまでは見たが、結果への効き方は推測)。カンマ区切りの金額が1円になるのは、利用者が普通にやりそうで一番気になる。

## デブリーフィング

- PROOF の5点はそろっている(2026-11-23 テストマネージャーが確認)。CH-001 は30分で時間枠に達した。
- 結論: 正しくない入力はどの欄でもエラーなしに0か先頭の数として計算される。BUG-008(カンマ区切りが1円)、BUG-009(NaN・∞)、BUG-010(固まって入力が失われる)を見つけた。RISK-028 が現実に起きることを確かめた。
- チャーター案「最後の6欄の結果への効き方」「全角数字」: 正しくない値の扱いがどの欄でも同じ(先頭の数として読む)ことを14欄で見ており、期待するふるまい自体が Q-010・Q-011 の回答待ちなので、新しいチャーターにせず見送る。全角数字は adb で入力できず試せていないことを、テストレポートで残るリスクとして伝える。
