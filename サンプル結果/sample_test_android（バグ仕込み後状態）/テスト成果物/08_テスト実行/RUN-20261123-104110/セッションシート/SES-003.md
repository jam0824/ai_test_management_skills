## 使ったテストデータ

TD-011 の 負の値(`-1`、`-1000000`)、百分率の範囲外(`101`、`1000`、`-1`、`-50`、`-100`)、極端に大きい値(`999999999999`、`9999999999999999999`、`200`(年齢))、TD-010 の桁の多い金額に近い値。加えて、9 を並べた長い数、1 のあとに0が40個の利回り。証跡は `SES-003/`。

## テストメモ

1. salary `-1000000`、investRate `101`(eventProb 0)→ `給与: ¥-71,667 (投資: ¥-72,383)`。負の年収が負の手取りとして出て、投資に回す額も負(投資から現金へ戻る)。投資の残高は負になり、利息で負が大きくなる(31歳1月 ¥-868,600 → ¥-903,344)。エラーは無い → 正の年収で投資率の範囲外を見る。
2. investRate `101`、interest `-100`、eventProb `1000` → 手取り ¥188,125 より多い ¥190,006 を投資に回し、現金が手取り以上に減る。発生率 1000% は毎月イベントが出る(100% と同じふるまい)。エラーは無い → 年齢の極端な値を見る。
3. startAge `200` で開始 → 結果の行が1行も出ない。もう一度押しても同じ。エラーも知らせも無いので、押せていないのか計算した結果が無いのか、利用者には分からない(課題。Q-001・Q-011)→ 負の大きな年齢を見る。
4. startAge `-1000000` で開始 → 押した直後から応答しなくなり、ANR のダイアログ。80秒たっても CPU 100%、メモリ使用率 8.7% → 15.0% と増え続けた。SES-002 の `-Infinity` と同じく、有限の値でも止まる(BUG-010 に追記)。強制終了した → 大きい金額を見る。
5. salary `9999999999999999999`、initialCash `999999999999` → 金額は指数表記にならず、3桁区切りで最後まで出て、行は折り返されて読める。ただし `¥322,500,000,000,421,696` のように、下の桁に計算の誤差がそのまま出る(手取り = 年収 × 0.86 − 税金 なので、ちょうどの値にならない数字が並ぶ)。表示の切れ・重なりは無い → もっと桁を増やす。
6. initialCash に 9 を320個 → adb の入力で途中までしか入らなかったらしく、`¥1,000,000,000,000,000,057,857,…` という 67桁ほどの金額になった。Infinity にはならなかった(入った桁数は確かめていない)。18:01 にこの操作の前の起動でアプリの ANR が出た(閉じて入れ直した)→ 負の値を組み合わせる。
7. initialInv `-1000000`、expenseCurrent `-100000`、investRate `-50`、eventProb `-1` → 生活費 `¥-100,000` で現金が増える。投資率 −50% で `投資: ¥-94,062`(投資から現金へ移る)。開始時投資残高の負は利息で負が大きくなる。発生率 −1% はイベントが出ない。どれもエラーは無い → 桁あふれを起こす。
8. startAge 90、initialInv 1000000、interest に 1 のあとに0が40個 → 97歳まで投資が数百桁の数字で表示され(切れずに折り返す)、98歳1月から `投資: ¥∞ 総資産: ¥∞` になる(BUG-009 に追記)。
9. startAge `-1000` → 開始の直後に一度 ANR のウィンドウが出たが、5秒後には消えて、結果が `-- -1000歳1月 --` から出た(1101年分)。−1000 では止まり続けず、−1000000 では止まり続ける。境目は見ていない。

アイデア・リスク:
- 負の値・範囲外の百分率は、どの欄でもそのまま計算に使われ、結果の符号が反転する(投資額や生活費が負になる)。誤入力に気づく手段は結果を読むことしかない。
- 開始年齢が大きく負だと止まる(BUG-010)。開始年齢が 100 を超えると結果が0行になる。どちらも年齢の範囲(Q-010)が決まれば防げる。

## 不具合

- BUG-010(追記): startAge `-1000000` でもアプリが応答しなくなる。手がかり: Purpose・User desires(入力しただけで止まり、入力を失う)。
- BUG-009(追記): 利回りがとても大きいと `¥∞` が出る。手がかり: Product(ほかの金額は数字で出る)、テストチャーター CH-002 の挙げた危険(読めない値がエラーの表示なしに出る)。
- BUG-002 と同じ「投資がマイナスになる」が、負の入力でも起きる(負の入力なので別の不具合にはしていない)。

## 課題

- 開始年齢が 100 を超えると、開始しても結果が0行で、何も知らせない。シミュレーションを何歳まで計算するか(Q-001)と、正しくない入力のふるまい(Q-011)の回答が要る。
- 負の金額・範囲外の百分率をどう扱うか(Q-010・Q-011)。今は符号が反転した結果がもっともらしく出る。
- 極端に大きな金額で、下の桁に計算の誤差が出る(表示は読める)。どこまでの金額を正しく扱うべきか(Q-010)。
