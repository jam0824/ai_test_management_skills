要求

テストベース: 仕様書.md(Web版のREADME。Android版も同じ仕様)と README.md(Android版の補足)。
仕様書.md のうち、Web版だけに当てはまる記述(retirement_simulator.html をブラウザで開く起動手順、test_retirement_simulator.html のテスト、ファイル構成、技術仕様の言語・ブラウザ要件)は Android アプリのテストベースにならないので、要求・仕様にしていない。
仕様書.md の「使用例」(ケース1〜4)は入力の例で、期待する結果が書かれていないので仕様にしていない。「注意事項」は Q-026 で扱いを確認している。
README.md のうち、ビルド手順・テストの動かし方は開発者向けの手順なので、要求・仕様にしていない(部品idと動作環境だけ取り込んだ)。

ID要求誰が何のために出典備考
REQ-001自分の条件を入力し、開始操作で老後までの資金の推移をシミュレーションできる老後の資金計画を立てたい利用者老後資金が足りるかの目安を知るため仕様書 冒頭、使い方 1・2
REQ-002入力欄に初期値が入っており、すべて入力しなくてもシミュレーションを試せる利用者手間なく使い始めるため仕様書 使い方 2. 設定項目(初期値の列)
REQ-003現役期間・退職後〜年金開始期間・年金受給期間の3つの期間で、それぞれの収入と生活費を使い分けて計算される利用者ライフサイクル全体の資金の動きを知るため仕様書 機能 包括的なライフサイクル計算、設定項目
REQ-004給与(年収)から社会保険料・所得税・住民税を差し引いた手取りで計算される利用者実際に使えるお金に近い形で計画するため仕様書 機能 詳細な手取り計算
REQ-005手取りの一部を投資に回し、利回りで増やし、現金が足りないときは投資資産を取り崩す計算ができる利用者投資を含めた資産の見通しを知るため仕様書 機能 投資シミュレーション
REQ-006転職・昇進などで年収が変わる年齢と年収を、何度でも設定・削除できる利用者現実的なキャリアパスで計画するため仕様書 機能 キャリア変更対応、使い方 3
REQ-007入院や家電故障などの突発的な支出が、設定した確率で起きるものとして計算される利用者予定外の出費があっても資金が持つかを知るため仕様書 機能 ランダムイベント
REQ-008月ごとの収入・生活費・突発的なイベント・現金・投資・総資産の残高を結果で確かめられる利用者どの時点で資金が増減・不足するかを知るため仕様書 使い方 4. 結果の見方
REQ-009入力した財務情報が外部に送られない利用者個人的な財務情報を安心して入力するため仕様書 プライバシー重視、技術仕様 オフライン動作、README.md 冒頭
REQ-010画面を回転しても、入力した内容と結果が消えない利用者入力をやり直さずに端末の向きを変えて見るためREADME.md 冒頭
REQ-011入力値が正しくないとき(範囲外・空欄・年齢の前後関係のおかしい組み合わせなど)に、誤った結果のまま気づかずに使うことがない利用者誤った計画を立てないため資料からの読み取り(仕様書 テスト内容の「エラーケーステスト: 異常値での動作確認」)仕様が無い。Q-010、Q-011
REQ-012画面の部品を決まった id で特定できるテスト担当者UI Automator や Appium で画面を自動操作して確かめるためREADME.md 画面の部品の id
