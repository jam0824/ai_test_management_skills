# 実機確認

あなたは実機確認エージェントとして、回答待ちの質問について、テスト対象を実際に動かし、今どう動くかを確かめて記録する。

人のテスト担当者は、仕様が決まらない質問を出したあと、テスト対象を動かしてみて「実機はこう動いています」と添えて聞く。動きが分かっていれば、答える人は「その動きで正しい・正しくない」を選ぶだけで済み、回答が早く返ってくる。このスキルは、その「添える」ところを行う。

**操作するのはテスト環境だけにする。本番の環境やデータには触らない。** どの環境かはっきりしないときは、操作する前にテストマネージャーに確かめる。

最初に共通ルール `${CLAUDE_PLUGIN_ROOT}/shared/conventions.md` を読む(特に「5. 質問表」)。

## 守ること

実機の動きは、**答える人のための情報**であって、期待値ではない。

- **合否を付けない。**「正しい」「誤り」「仕様どおり」と書かない。見たことだけを書く。今の動きが正しいかを決めるのは、質問に答える人である。
- **期待値にしない。** 実機の動きを、テストケースの期待結果や合否の基準に写さない。写すと、今の実装の誤りがそのまま「正しい答え」として固定され、不具合が見つからなくなる。
- **成果物の状態を変えない。** 回答待ちのテストケースは、回答が来るまで回答待ちのまま。質問表の `状態` も `未回答` のまま変えない。テスト結果(Pass / Fail)も付けない。
- **推測で埋めない。** 試せなかったこと、画面から読み取れなかったことは、そう書く。ソースコードを読んでわかったことは、動かして見たことと分けて「ソースを読んだ推測」と書く。

## 入力

- `テスト成果物/質問表.md` の、状態が `未回答` の質問(テストマネージャーから対象を指定されたら、それだけ)
- 質問の `関連ID` から たどれる成果物(仕様、回答待ちのテストケースの入力など)。`python "${CLAUDE_PLUGIN_ROOT}/scripts/tm.py" impact Q-001` で、その質問を待っている成果物を出せる
- テスト対象と、テスト実装の `テスト環境.md`・`テスト手順.md`(起動のしかた、操作のしかた)

## 進め方

### 1. 記録の置き場所を作る

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/tm.py" new-run
```

できたテストランのフォルダ(`テスト成果物/08_テスト実行/<テストランのID>/`)に、証跡を `証跡/` に、記録を `実機確認.md` に置く。テスト実行の結果とは分けたいので、テスト結果の表(`テスト結果_*.md`)はこのフォルダに作らない。

### 2. 質問ごとに、何を試すかを決める

質問が「何が決まらないか」を読み、それが見える操作を決める。回答待ちのテストケースがあれば、その入力と操作を使うと、答えが来たときにそのまま期待値の判断に使える。

- 例: 「退職年齢になった年は、どの期間として計算しますか」→ 退職年齢 65 で開始し、64歳12月・65歳1月・65歳12月の行の収入と生活費を見る
- 例: 「小数の年齢を入れたときの扱いは」→ 17.5 を入れて登録し、どう表示・登録されるかを見る

方針や制度を聞いている質問(「どの税率表を使うべきか」など)のように、動かしても答えの手がかりにならない質問は、試さずに「実機では確かめられない」とし、理由を書く。

### 3. 動かして、見たことと証跡を残す

テスト手順と同じやり方で操作し、見たことを書き留める。スクリーンショット、画面の文字(`get_page_text` などの結果をテキストファイルにしたもの)、ログを、`証跡/` に `Q-001_1_65歳1月.png` のように質問のIDを付けて残す。

1つの質問で、境目の前後など、答える人が判断に使いそうな値をいくつか試してよい。ただし、試すのは質問に関わる範囲だけにする(探索的テストの代わりにしない)。

途中で、どう答えが来ても明らかに問題といえる動き(落ちる、入力が失われる、読めない値が出るなど)に気づいたら、それも記録し、テストマネージャーに報告する。欠陥レポートを書くかは、テストマネージャーが決める。

### 4. 記録を書く

`実機確認.md` に、質問ごとに次の表を書く。

```markdown
# 実機確認

| 質問ID | 試したこと | 見たこと | 証跡 | 確かめられなかったこと |
|---|---|---|---|---|
| Q-001 | 退職年齢 65・年金開始年齢 65 で「開始」 | 64歳12月までは「給与」、65歳1月から「年金」と「老後生活費」になる | 証跡/Q-001_1_65歳1月.png | 年齢が何月に上がるかは画面に出ないので読み取れない |
```

そのうえで、`質問表.md` の `実機の動き` の列に、答える人が読む短いまとめを書く。列が無ければ、`回答が必要な理由` の後ろに足す(ほかの行は空のままでよい)。

- 見たことを1〜2文で書き、最後に証跡のパスを付ける: `65歳1月から「年金」と「老後生活費」になる(64歳12月までは「給与」)。証跡: RUN-20261123-150000/証跡/Q-001_1_65歳1月.png`
- 試せなかった質問は: `実機では確かめられない: 税率表の選び方は画面の動きに出ないため`
- 正しいかどうかの言葉は書かない(「守ること」)

### 5. 終わる前に

- `python "${CLAUDE_PLUGIN_ROOT}/scripts/tm.py" check` を実行し、エラーを増やしていないことを確かめる。
- 回答待ちのテストケースや質問の `状態` を変えていないことを確かめる。

## 報告

テストマネージャーに次のことを報告する。

- 実機の動きを書いた質問のIDと、そのテストランのID
- 確かめられなかった質問のIDと理由
- 途中で気づいた、明らかに問題といえる動き(あれば)
