# テスト分析レビュー

テストマネージャーとして、テスト分析の成果物をレビューする。テスト条件に無いことは、テストケースにならず、テストされない。「すべてのテストアプローチにテスト条件がある」だけでは足りず、リスクの高いところを十分な厚さで拾えているかを見る。

進め方は、共通ルール `${CLAUDE_PLUGIN_ROOT}/shared/conventions.md` の「8. レビューの進め方」に従う。確認のコマンドは `check --stage analysis`。

## レビューするもの

- `テスト成果物/04_テスト分析/テスト分析.md`
- `テスト成果物/質問表.md`(工程が「テスト分析」の質問)

## 照らし合わせる入力

テスト分析スキルと同じ入力(`03_テスト計画/テスト計画.md`、`01_要求仕様/要求.md`、`仕様.md`、`質問表.md`、`02_リスク分析/リスク分析.md`)。

## 見ること

- **フィーチャー**: すべての仕様が、どれかのフィーチャーに入っているか。機能以外(性能・セキュリティ・使いやすさ)のフィーチャーが抜けていないか。合否を出せないフィーチャーが、質問表に書かれているか。
- **テスト条件の抜け**: すべてのフィーチャーとテストアプローチに、テスト条件があるか(`check` の警告を1件ずつ見る)。
- **リスクの高いところの厚さ**: リスクの高いところに、正常な場合・境界値・異常な入力・状態の移り変わりなどのテスト条件がそろっているか。高いリスクなのに、正常な場合のテスト条件しか無いものは P1 にする。
- **仕様の構造**: 仕様の中の入力項目、有限なリスト、境界値、状態、動作環境が、抜けなく拾われているか。仕様を自分で読み、構造を数えて確かめる。
- **3段階**: 仕様から出したもののほかに、一般的な品質の観点と、見逃しそうなバグから出したテスト条件があるか。自分でも「この分析のままテストしたら、どんなバグを見逃すか」を考え、拾えていないものを指摘にする。
- **優先順位**: 優先順位が、紐づくリスクのリスクレベルと合っているか。
- **リスクの紐づけ**: リスクIDが、そのテスト条件が実際に確かめるリスクになっているか。関係の薄いリスクに紐づけて、カバーしたことにしていないか。
- **テストオラクル**: すべてのテスト条件に、テストオラクルが決まっているか。テスト対象の今の動きを正しいとみなしていないか。
- **質問表**: 質問表に書くべきことが漏れていないか。質問にすべきなのに、推測で期待する結果を決めたテスト条件がないか。回答待ちのテスト条件に、質問のidが書かれているか。
- **工程の境目**: テスト条件が「何を確かめるか」にとどまっているか。境界の前後のどの値を試すか、手順、具体的な期待結果まで書いてしまっていないか(それはテスト設計とテスト実装で決める)。

## 直すときに気をつけること

- 新しいリスクや、足りないテストアプローチに気づいたら、リスク分析やテスト計画に書き足さず、「後からわかったことの扱い」に乗せる。
- 仕様に答えが無いことは、直さずに質問表に書く。
