# E2E自動テストスクリプトレビュー

テストマネージャーとして、E2E自動テストスクリプトをレビューする。スクリプトは、動けば Pass を出す。だから「動くか」ではなく、「その Pass が、ローレベルテストケースの期待値を確かめた結果か」を見る。

進め方は、共通ルール `${CLAUDE_PLUGIN_ROOT}/shared/conventions.md` の「8. レビューの進め方」に従う。確認のコマンドは `check --stage e2e`。

## レビューするもの

- E2E自動テストスクリプトの本体と設定(プロジェクトのテスト用フォルダ)
- `テスト成果物/07_E2E自動テストスクリプト/スクリプト一覧.md`、`未実装.md`

## 照らし合わせる入力

E2E自動テストスクリプト作成スキルと同じ入力(`06_テスト実装/` のローレベルテストケース・テストデータ・テスト環境、テスト対象)。

## 見ること

- **抜け**: 実施方法がE2E自動テストのローレベルテストケースが、すべてスクリプトになっているか。なっていないものは、理由つきで記録され、手動テストに回すよう報告されているか。
- **idの対応**: テストの名前の先頭に、ローレベルテストケースのidが付いているか。テスト1件がテストケース1件になっているか。`スクリプト一覧.md` と、実際のスクリプトが合っているか。
- **アサーション**: 期待値を本当に確かめているか。次のようなテストがあれば P1 以上にする。
  - 確認が無い、または操作が終わったことしか確かめていないテスト
  - 必ず合格するテスト(期待値をスクリプトの中で実装と同じ計算で作っている、画面から取った値を同じ値と比べている、など)
  - 確認が条件分岐や try の中にあり、通らなくても合格するテスト
- **期待値**: アサーションの期待値が、ローレベルテストケースの期待値と一致しているか。事前条件・入力データ・事後条件も、ローレベルテストケースのとおりか。
- **テストデータ**: テスト実装で作ったファイルを読み込んでいるか。スクリプトに埋め込まれていないか。
- **毎回同じ結果になるか**: 決まった秒数だけ待つ作りがないか。テスト同士で状態を共有していないか(1件だけ実行しても、順番を変えても同じ結果になるか)。乱数や日時で結果が変わる部分が固定されているか。
- **操作のしかた**: 利用者と同じように、画面から操作しているか。確かめたい動きを、内部の関数の呼び出しやデータの直接の書き換えで済ませていないか(仕様とテストオラクルが内部の計算値で判定すると決めているものは除く。そのときも入力が画面からか、根拠がコメントにあるかを見る)。証跡の出力先(`outputDir`)が設定ファイルのあるフォルダの中か。
- **結果と証跡**: 実行結果が、テストごとにidつきで出るか。失敗したときに、スクリーンショット・録画・ログが残る設定か。
- **合格させるための変更**: 期待値を緩める、確認を消す、失敗するテストをスキップにする、といった変更がないか。
- **一度実行した結果**: スクリプト自体の誤りで止まるテストが残っていないか。

## 直すときに気をつけること

- ローレベルテストケースの誤りに気づいたら、ローレベルテストケースを書き換えず、「後からわかったことの扱い」に乗せる。
- スクリプトを直したら、もう一度実行して、スクリプトの誤りで止まらないことを確かめる。テスト対象の不具合と考えられる失敗は、そのまま残す。
