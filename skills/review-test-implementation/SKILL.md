# テスト実装レビュー

テストマネージャーとして、テスト実装の成果物をレビューする。ここで一番見るべきなのは**期待値の出どころ**である。テスト対象を動かして出た値を期待値にしたテストは、必ず合格し、何も確かめない。そういうテストが混ざると、Pass の数を信じられなくなる。

進め方は、共通ルール `${CLAUDE_PLUGIN_ROOT}/shared/conventions.md` の「8. レビューの進め方」に従う。確認のコマンドは `check --stage implementation`。

## レビューするもの

- `テスト成果物/06_テスト実装/` のローレベルテストケース、テストデータ、テスト手順、テストスイート、テスト環境、`未実装.md`

## 照らし合わせる入力

テスト実装スキルと同じ入力(`05_テスト設計/テスト設計.md`、`01_要求仕様/仕様.md`、テスト対象)。

## 見ること

- **抜け**: すべてのハイレベルテストケースが、ローレベルテストケースになっているか。手動テストのものには、テスト手順があるか。なっていないものは、理由つきで `未実装.md` に記録されているか。黙って落とされたものがないか。
- **回答待ち**: テスト設計で回答待ちのテストケースが、推測で期待値を決めて実装されておらず、回答待ちとして `未実装.md` に記録されているか。
- **期待値の出どころ**: 期待値が、ハイレベルテストケースに書かれたテストオラクルから決まっているか。テスト対象の実装から写した期待値がないか。計算で決まる期待値は、いくつかを選んで、仕様の式から自分で計算し直して比べる。
- **具体さ**: 入力データと期待値が、そのまま実行できる具体さか(「有効な値」「正しく表示される」のような書き方が残っていないか)。ハイレベルテストケースのカバレッジアイテムを、実際に通す値になっているか。
- **テストデータ**: テスト手順やテストケースに埋め込まれず、ファイルとして分けて置かれているか。個人情報や本番のデータを使っていないか。
- **テスト手順**: 準備・操作と確認・後片付けがあるか。別のエージェントが、手順だけを見て同じように実行できる細かさか。どこで何を期待値と比べるかが書かれているか。手順を一度そのとおりに試した記録が `テスト環境.md` にあるか。
- **テストスイート**: 実行の順番が、優先順位と依存関係に合っているか。探索的テストの準備(時間枠、テストデータ、テスト環境)が書かれているか。
- **テスト環境**: スモークテストが済んでいて、結果が書かれているか。テスト環境要件に書かれた操作まで試しているか。「できなかった」結果は、やり方を変えて試し直したうえでのものか(それをもとにテストを外していれば、とくに確かめる)。本番の環境やデータに触るものになっていないか。
- **カバレッジ**: テスト設計で出したカバレッジアイテムのうち、ローレベルテストケースで通せていないものがどれかが、わかるようになっているか。

## 直すときに気をつけること

- テスト条件やハイレベルテストケースの不足・誤り、テストオラクルで期待値が決められないものに気づいたら、前の工程のドキュメントに書き足さず、「後からわかったことの扱い」に乗せる。
- 期待値を直すときも、テスト対象を動かした結果に合わせない。仕様とテストオラクルから決め直す。
