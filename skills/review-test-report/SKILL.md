# テストレポートレビュー

テストマネージャーとして、テストレポートをレビューする。レポートは、テストを依頼した人が判断に使う。読む人は成果物まで戻って確かめないので、レポートに書かれたことが成果物と合っているかを確かめるのは、ここが最後になる。

進め方は、共通ルール `${CLAUDE_PLUGIN_ROOT}/shared/conventions.md` の「8. レビューの進め方」に従う。

## レビューするもの

- `テスト成果物/09_テストレポート/<日時>/テストレポート.html`(実際に開いて見る。ブラウザを操作できるツールがあれば表示して確かめる。`file://` を開けないときの開き方は `create-test-report` の「4」と同じ)
- `テスト成果物/09_テストレポート/判定.md`

## 照らし合わせる入力

テストレポートスキルと同じ入力(すべての工程の成果物)。数字は、次のコマンドで自分で数え直して比べる。

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/tm.py" check
python "${CLAUDE_PLUGIN_ROOT}/scripts/tm.py" metrics
```

## 見ること

- **ファーストビュー**: ファーストビューだけで「やるべきことをやったか」と「問題点は何か」がわかるか。スクロールしないと大事なことが出てこない、ということがないか。
- **終了条件の判定**: テスト計画のすべての終了条件に判定があるか(未判定が残っていないか)。判定が、`metrics` の数字と、終了条件の「測り方」に合っているか。満たしていないものを「満たした」にしていないか。根拠に、数字やidが書かれているか。
- **数字**: レポートの数字が、数え直した値と一致しているか。実行していないテストケース(未実行・ブロック・未実装)を、カバーした数に含めていないか。割合に分母が書かれているか。
- **カバレッジ**: すべての要求とリスクが、カバレッジの表に出ているか。リスクがリスクレベルの高い順に並んでいるか。
- **トレーサビリティ**: リンクが切れずにたどれるか。要求を1つ選んで、カバレッジの一覧を開きながらテスト結果・証跡まで、欠陥レポートを1つ選んで要求・リスクまで、実際にたどってみる。一覧の「実行 x/y」と色帯が、metrics の数字と合っているか。`check` にエラーが残っていないか。
- **省かれていること・弱められていること**: 修正されていない不具合、カバーできていない要求とリスク、未回答の質問、計画からの変更、今の版で確かめていない結果が、省かれたり、評価の言葉でぼかされたりしていないか。判定.md の文章が、数字と食い違っていないか。
- **計画からの変更・戻しの記録**: 戻し記録と未実装の記録にあることが、レポートに出ているか。
- **基づいている成果物**: レポートを作った時点の成果物(snapshot)が、一緒に保存されているか。レポートを作ったあとで成果物が変わっていないか。変わっていれば、レポートを作り直す。

## 直すときに気をつけること

- 判定や文章の誤りは、`判定.md` を直して、`python "${CLAUDE_PLUGIN_ROOT}/scripts/tm.py" report` でレポートを作り直す。できたHTMLを直接書き換えない(成果物と食い違うため)。
- 数字が成果物と合わないときは、成果物の側の誤り(紐づけの切れ、結果の付け間違い)なので、レポートでつじつまを合わせず、「後からわかったことの扱い」に乗せる。
- 作り直したら、古いレポートのフォルダは残したままでよい(どの時点のレポートかがわかる)。
