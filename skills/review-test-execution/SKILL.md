# テスト実行レビュー

テストマネージャーとして、テスト実行の結果をレビューする。「すべて Pass です」という報告を、そのまま信じない。その Pass が、期待値と比べた結果であること、証跡で確かめられることを見る。

進め方は、共通ルール `${CLAUDE_PLUGIN_ROOT}/shared/conventions.md` の「8. レビューの進め方」に従う。確認のコマンドは `check --stage execution`。

## レビューするもの

- `テスト成果物/08_テスト実行/<テストランのID>/` の実行情報、テスト結果、証跡、セッションシート
- `テスト成果物/08_テスト実行/欠陥レポート.md`

## 照らし合わせる入力

テスト実行スキルと同じ入力(`06_テスト実装/` のテストスイート・ローレベルテストケース・テスト手順、`07_E2E自動テストスクリプト/`、`05_テスト設計/` のテストチャーター)。

## 見ること

- **結果の抜け**: テストスイートのすべてのローレベルテストケースに、結果が付いているか。ブロックと未実行に、理由があるか。
- **Pass の根拠**: Pass に証跡があるか(E2E自動テストはidつきの実行結果、手動テストはスクリーンショットなど)。手動テストの Pass をいくつか選び、証跡を自分で開いて、期待値と本当に一致しているかを見る。スクリプト全体の成功から Pass を付けたケースがないか(`テスト結果_E2E自動.md` は `e2e-results` が作ったものか、PlaywrightのJSONにそのidの結果があるか)。
- **Fail の扱い**: Fail に原因の分析があるか。テスト対象の不具合には欠陥レポートがあるか。テストウェアの誤りは、テスト対象の不具合として報告されず、戻し方に乗せるよう報告されているか。Fail を Pass にするために、テストケースやスクリプトが書き換えられていないか。
- **欠陥レポート**: 再現できる手順、証跡、期待値と実際の結果、重要度がそろっているか。関連IDが、見つけたテストケースかセッションを指しているか。同じ不具合が2回書かれていないか。重要度が、要求や利用者への影響と合っているか。
- **探索的テスト**: セッションシートの項目がそろっているか。テストメモから、触る・分析する・設計するの繰り返しが追えるか(操作の一覧だけになっていないか)。問題と判断した手がかりが書かれているか。時間枠を守り、時間の内訳が書かれているか。デブリーフィングが済んでいるか(済んでいなければ、ここで行う)。
- **実行の記録**: テスト対象・テストツール・テストウェアの版が記録されているか。前のテストランの結果が上書きされていないか。
- **環境**: テスト環境だけを操作しているか。
- **報告されないまま残っていること**: テスト結果のメモやセッションシートの中に、前の工程で決めること(仕様の疑問、足りないテスト条件、新しいリスク、環境の不具合、手順の誤り)が、報告されないまま残っていないか。残っていれば拾って、戻し方に乗せる。

## 直すときに気をつけること

- 結果そのもの(Pass / Fail)を、レビューで書き換えない。付け間違いだと判断したら、理由をメモに書いたうえで、そのテストケースを実行し直させる。
- 足りない証跡や原因の分析は、実行したエージェントに補わせるか、実行し直させる。
- 探索的テストのデブリーフィングは、PROOF の5点をセッションシートで確かめ、結論と次に必要なテストチャーターの案をセッションシートの「デブリーフィング」に書く。

## 結果

`テスト成果物/08_テスト実行/<テストランのID>/レビュー結果.md` に書く。
